# 开发流程

1. **调查**：确认目标服务、Git 基线及已有改动，阅读相关业务、代码和测试，识别复用点与未知项。
2. **需求与设计**：在 [变更记录](../changes/README.md) 明确范围、验收、契约、兼容性及文档影响；关键选择关联架构决策。
3. **实现与验证**：遵循 [编码规范](coding.md)，运行仓库已有检查；功能、修复和关键重构覆盖正常、边界、错误及重要兼容行为。
4. **交付**：记录实际命令、环境、结果和未覆盖项，同步长期文档。验收、必要验证及文档同步完成后，才标记已完成。

小改动可合并记录；纯文档修订不建需求包。文档与代码通过 CHG 编号、提交关联；未提交时记录分支、基线及文件清单。
