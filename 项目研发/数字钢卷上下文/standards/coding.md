# 编码规范

来源：用户全局约定；具体语言与工具遵循目标仓库。

- 优先级：现有约定 → 架构清晰 → 复用 → 可理解性 → 局部技巧。职责分层，不做无关重构或预设抽象。
- 命名遵循 [术语表](../business/glossary.md)，表达实体、动作及必要单位，避免含糊缩写。
- 函数单一职责、控制流直观；使用明确类型。公共契约说明输入、输出、错误、前置条件、副作用和兼容性。
- 修改公共实现时检查调用方；复用语义一致且共同变化的逻辑。
- 新增或修改代码提供必要中文文档注释，已有语言规范优先；解释业务、原因、约束和边界，不逐行复述。复杂算法、并发、事务等说明不变量和异常路径。
- 非显而易见的字段注明含义与约束：标识符的唯一性，数值单位/精度/范围，时间格式/时区，布尔两种含义，状态转换，集合顺序/重复/空值，配置默认值/无效值处理，敏感性与日志限制。
- 复用既有接口、日志、错误和配置方式；数据变化评估迁移与兼容性，错误信息不得泄露敏感数据。
- 注释同步更新；TODO 等标记写明原因与处理条件。
- 创建或修改 Git 提交前查看最近提交风格；默认 `type: 中文描述`，冒号后一个空格。
