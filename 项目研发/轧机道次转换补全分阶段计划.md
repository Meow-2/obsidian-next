# 分阶段实现与审查计划

每轮只实现一个小目标，完成代码和对应测试后暂停，供你审查。审查通过再进入下一步，不提前混入后续功能。

每一步交付说明包含：改了什么、关键代码位置、验证结果，以及下一步将使用的接口。

## 1. 支持独立对外实例

**目标**：同一个 JAR 可以启动不属于任何机组的对外实例。

- 增加 `tracking.mode=unit|external`，默认 `unit`。
- external 模式不要求 `tracking.unit`。
- 隔离实时启动流程、MQTT 和 RocketMQ 装配及依赖链。
- 增加 external profile，保留现有机组部署兼容性。

**验收**：external 模式不配置机组和消息服务也能启动；默认模式仍执行原有跟踪初始化。

**审查重点**：运行模式条件是否覆盖完整，有无改变现有机组实例行为。

## 2. 按指定机组获取 Cube 历史配置

**目标**：对外实例能显式读取 `zrm1/status`，不依赖实例机组。

- 给 Cube 查询增加显式机组入口，保留旧入口兼容。
- 复用现有 status 配置转换器。
- 根据配置路径定位必要点位，解析 `code`、`cubeKey` 和 TDengine 对象名。
- 返回独立的历史配置快照，不刷新或修改实时配置缓存。

**验收**：能解析道次、速度、方向、厚度及设备卷号和长度；缺失、重复或非法映射明确失败。

**审查重点**：配置复用方式、点位定位规则，以及是否误用实时缓存。

## 3. 实现 TDengine 只读历史访问

**目标**：提供可独立验证的历史读取能力，暂不识别道次或调用质量接口。

- 新增 `PointHistoryRepository` 及 REST 查询实现。
- 支持时间范围内有序分页、指定时间之前的最近值查询。
- 同对象字段合并读取，校验对象和字段。
- 统一上海时间输入和内部 `Instant`，保留原始精度。
- 默认每页 2000 条，完整读取，避免分页遗漏。

**验收**：覆盖空结果、多页、时间边界、查询失败和时间转换；用只读样本核对查询结果。

**审查重点**：SQL 构造、游标推进、时间精度及错误处理。

## 4. 实现纯道次事件识别

**目标**：输入历史道次序列，输出需要补全的上一道次区间。

- 独立实现连续段识别，不依赖 Spring、数据库或质量接口。
- 递增结算旧段；跳号只结算实际观测旧段。
- 回退、归零不结算，重复道次号在不同生产周期中独立处理。
- 按切换时间归属 `[startTime,endTime)`。
- 固定回溯 1h，无法确认起点的段返回跳过原因。
- 跨页保留识别状态。

**验收**：用人工构造序列验证递增、跳号、回退、异常值和首尾边界。

**审查重点**：事件定义、区间边界和回溯不足判定。这一步不产生任何质量写入。

## 5. 计算道次首末帧和质量数据

**目标**：给定一个已确认完整的道次区间，生成待发送的道次数据。

- 速度严格大于 `quality_min_speed`，确定第一帧和最后一帧时间。
- 抽取现有设备选择规则供实时和历史共用，保持实时行为不变。
- 按末帧确定开卷侧卷号、卷取侧长度及出口厚度。
- 跨点位使用此前最近值，默认最大滞后 5 秒，保留来源时间。
- 缺失、过期、无效或身份不一致时跳过，不移动首末时间。
- 复用卷号清洗和 `CellCodeResolver`。

**验收**：覆盖速度阈值、方向反转、首道次 POR、后续 TR、字段过期和数据异常；原 status 测试通过。

**审查重点**：共享规则的抽取是否安全，以及历史首末帧和字段来源是否准确。

## 6. 补齐重复生产次数并接入质量调用

**目标**：完成单个道次的端到端写入能力。

- 新增按道次开始时间查询历史最大重复次数的只读方法。
- 严格使用 `create_time < passStartTime`，无记录默认 1，不分配新次数。
- 组装现有 `RollingPassOutput`。
- 直接复用 `QualityServiceGateway` 的请求转换及三次尝试。
- 返回单道次成功、跳过或失败结果，不使用只记日志的异步发送器。

**验收**：覆盖时间截断查询、默认次数、请求字段和重试行为；核实质量接口重复写入覆盖语义。

**审查重点**：次数查询口径、质量实际入参，以及失败能否被调用方准确感知。

## 7. 实现内存异步任务编排

**目标**：把前面能力串成可查询的后台任务。

- 专用线程池默认单工作线程、队列容量 10。
- 任务开始时固化 Cube 配置，按切换时间顺序处理道次。
- 单道次失败后继续；全局扫描失败终止并保留已有结果。
- 保存任务阶段、进度、计数和道次明细。
- 默认保留结束结果 24h，最多保留 1000 个结束任务。
- 重复提交创建新任务；不增加任务表或重启恢复。

**验收**：覆盖队列拒绝、部分失败、并发查询、清理和资源上限。

**审查重点**：状态转换、线程安全、内存边界和异常传播。

## 8. 开放 HTTP 接口并完成部署验收

**目标**：交付可调用、可审计的对外服务。

提供：

```text
POST /openapi/retracking/zrm1/status/pass-output
GET  /openapi/retracking/tasks/{taskId}
GET  /openapi/retracking/tasks/{taskId}/passes
```

- 提交参数仅为 `startTime`、`endTime`，上海时间严格解析。
- 默认最大跨度 24h，异步受理返回 HTTP 202；参数错误 400，队列满 429。
- 查询沿用 `R<T>`，道次明细分页返回。
- 补充接口、配置、异常原因和单副本部署说明。
- 执行完整测试和打包，并用历史样本联调核对。

**验收**：external 实例从提交到结果查询完整可用；成功请求可核对，跳过和失败有原因；无实时订阅或运行态修改。

**审查重点**：公开接口契约、最终联调结果及部署配置。

## 执行约定

- 从目标 1 开始，逐步推进。
- 每步只包含该目标必需的实现及回归测试。
- 线上历史读取保持只读；实际质量写入仅在明确的联调环境和范围内验证。
- 每步完成后交付审查，不自动进入下一步，也不自动提交 Git。
- 线上 schema、历史配置适用性和质量覆盖语义以联调证据为准；任务重启丢失、固定 1h 回溯及默认 5 秒最近值有效期沿用已确认选择。
