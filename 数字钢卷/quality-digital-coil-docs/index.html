切片算法模拟

拖动参数观察有效卷段如何被划片。采样窗口结束位置还会增加“检测仪距离差”，但下一片起点仍只增加片长，因此窗口可能重叠。

effectiveStart = headCutLengthSum ?? 0
effectiveEnd = outMatLength - (tailCutLengthSum ?? 0)
piece[i].start = effectiveStart + i × pieceLength

厚度对齐

以最终加工单元为基准。若最终卷厚 1 mm、片长 10 m，上游厚 2 mm，则上游对齐片长为 5 m。

alignLength = standardPieceLength × baseThick / currentThick

插值与聚合

目标长度命中采样点时复制；落在两点之间线性插值；超出首尾时沿用边界值。所有目标点求均值并四舍五入到 3 位小数。

y = y₁ + (y₂-y₁) × (x-x₁)/(x₂-x₁)

当前实现观察

以下是源码现状，而不是设计目标。它们适合作为联调断点、测试用例或后续重构清单。

原始 SQL 入口 高

/tdengine/query/sql 接收并通过 @Select("${sql}") 执行完整 SQL；若对非可信调用方开放，会带来注入和越权查询风险。

字符串使用引用比较 高

mergePaths 使用 cur.getMatType() == "1"，应使用值比较；当前可能无法稳定识别并卷节点。

缺陷边界公式需验证 中

ceil((y-start)/piece)+1 会让起点后极小正值进入第 2 片；totalPieces 又额外 +1，与实际区间数可能不一致。

空列表先 get(0) 中

跨单元服务在检查首机组查询结果数量之前先执行 firstDcCellsMaterialBloodList.get(0)。

过程点完整性假设 中

参数存在性校验已注释，插值会对缺失值自动拆箱；同时算法假定 DataPoint 已按 length 排序、列表非空。

动态 SQL 拼接 中

表名、列名与卷号直接拼接。表列名来自元数据，但卷号和调试 SQL 仍需白名单、参数化或隔离。

配置读取但未落库 提示

outCoilPieceTable 已解析，却没有写入；当前“输出”是 HTTP VO，不是持久化切片表。

未完成字段与依赖 提示

thickRatio、左右累计切边未赋值；dcUnitsMaterialService 已注入但未使用；Unit 方向配置未进入主链路。

敏感配置 高

源码配置包含数据库连接凭据。本页不展示具体值，建议迁移到环境变量或密钥管理，并轮换已提交的凭据。

已有的保护

片长、结束长度和检测仪距离差具备基础校验；数值类型可在数据立方解析时转换；TDengine byte[] 会转为 UTF-8 字符串。
