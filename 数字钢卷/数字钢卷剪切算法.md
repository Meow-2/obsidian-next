## 剪切跟踪算法流程
配置转换器读取机组的剪切配置并完成校验，配置主体包含`enable`、`mqtt_topic`和`tracking`。`tracking`中的主要字段如下：

- `point_prefix`：MQTT点位统一前缀。
- `mode`：判型模式，支持`CONTINUOUS`（连续线）和`DISCONTINUOUS`（非连续线）。
- `tail_experience`：开卷机侧区分切尾与分切的剩余长度阈值，必须大于等于0。
- `shear_experience`：区分同一次完整剪切和下一次完整剪切的剩余长度差阈值，必须大于等于0。
- `uncoiler_shear_point`、`coiler_shear_point`：开卷机侧和卷取机侧剪刀列表。每把剪刀包含：
  - `name`、`type`、`normal_pos`：触发点名、点位类型和正常位；触发点必须为boolean。
  - `type_codes`：必须分别配置互不重复的`head`、`slice`、`tail`数据库编码。
  - `device_codes`：允许关联的有序设备代码列表；新配置优先使用该字段。`device_code`保留用于兼容单设备旧配置。
  - `shear_settings.default`：可选固定类型`head`、`tail`或`slice`；配置后跳过颜色或光栅判型。
  - `shear_settings.head/tail`：切头、切尾的`number`设定刀数点和`length`单刀长度点。开卷机侧以及非连续线卷取机侧使用该配置。
  - `color_point`：连续线未配置`default`时必填，用于颜色判型。
  - `grating_points`：非连续线未配置`default`时必填；每项必须是boolean并配置`has_coil`。当前值等于`has_coil`表示该光栅占位，所有配置光栅都占位才视为连续占位。
  - `front_welder/behind_welder`：连续线卷取机侧切尾/切头配置，包含`sample_pieces`、`scrap_pieces`以及片长点。
  - `welder_pieces`：连续线出口飞剪的焊缝废料总片数点，可不配置；不配置按0处理，点位值小于0时该剪切事件无效。

设备选择规则：算法先在`device_codes`中按配置顺序查找与该侧`statusContext.current.deviceCode`相同的设备；没有命中时固定回退到列表最后一个代码对应的`candidate`。回退candidate不存在、`dataComplete=false`，或最终两侧任一端缺少卷号、生产次数、剩余长度时，本剪刀事件跳过。连续线自动判型还要求两侧颜色号和`color_point`有效；颜色在比较前会去除不可见字符并进行数值规范化。

触发与隔离规则：算法按配置顺序处理每把剪刀，仅当上一帧信号等于`normal_pos`且当前帧信号有效并离开`normal_pos`时产生剪切事件。没有上一帧、返回正常位、信号缺失或不可转换时不产生记录。单把剪刀计算异常只跳过该点，不影响同一MQTT帧内其他剪刀。

运行态与刀次规则：算法在每帧先同步各配置设备的开卷机/卷取机绑定；设备代码、卷号或生产次数变化时不继承旧卷计数。每个物料按`head/slice/tail`分别保存`shear_no`、`cut_no`和`lastPorRemainLength`：

- 没有完整历史计数时从`shear_no=1、cut_no=1`开始。
- `delta = lastPorRemainLength - 当前开卷机剩余长度`。
- 当`0 <= delta < shear_experience`时属于同一次完整剪切，`cut_no+1`。
- 当`delta < 0`或`delta >= shear_experience`时开始下一次完整剪切，`shear_no+1、cut_no=1`。

### 剪切类型判定

若`shear_settings.default`非空，算法直接使用该类型，不再读取颜色点或光栅点。未配置默认类型时按模式判定。

连续线开卷机侧：

- 两侧颜色不同且剪刀颜色等于开卷机颜色：`head`。
- 两侧颜色不同且剪刀颜色不等于开卷机颜色：`tail`。
- 两侧颜色相同且开卷机剩余长度小于等于`tail_experience`：`tail`。
- 两侧颜色相同且开卷机剩余长度大于`tail_experience`：`slice`。

连续线卷取机侧（出口飞剪）：

- 剪刀颜色等于卷取机颜色：`slice`。
- 颜色不等时，先推演卷取机侧`tail`的下一刀`cut_no`。焊缝总片数`welder_pieces`按整数除以2分配给前段，余数归后段。令`frontWelderPieces = welder_pieces / 2`，`tailLimit = front_welder.sample_pieces + front_welder.scrap_pieces + frontWelderPieces + 1`：
  - 推演的`cut_no <= tailLimit`：`tail`。
  - 推演的`cut_no > tailLimit`：`head`。

非连续线开卷机侧：

- 两侧卷号相同且开卷机剩余长度小于`tail_experience`：`tail`。
- 两侧卷号相同且开卷机剩余长度大于等于`tail_experience`：`slice`。
- 两侧卷号不同且所有光栅都占位：`head`。
- 两侧卷号不同且至少一个光栅未占位：`tail`。

非连续线卷取机侧：

- 两侧卷号相同：`slice`。
- 两侧卷号不同且所有光栅都占位：`tail`。
- 两侧卷号不同且至少一个光栅未占位：`head`。

### 物料归属、长度与设定数量

记录归属规则如下：

| 剪刀侧 | `head` | `tail` | `slice` |
| --- | --- | --- | --- |
| 开卷机侧 | 对应开卷机 | 当前卷取机 | 对应开卷机 |
| 卷取机侧 | 当前开卷机 | 对应卷取机 | 对应卷取机 |

- `head/tail`首刀与后续刀次都具有配置长度和设定数量。
- 开卷机侧以及非连续线卷取机侧：`shear_length`取对应`head/tail.length`，`set_number`取对应`head/tail.number`。
- 连续线卷取机侧：`tail`使用`front_welder`，`head`使用`behind_welder`。`set_number = sample_pieces + scrap_pieces + 本段welder_pieces分摊值`；前段取整数除以2，余数归后段。
- 连续线卷取机侧片长优先读取所用方向的公共`length`。未配置公共`length`时，按片序读取`sample_length`或`scrap_length`：切尾片序为`cut_no - 1`，切头片序为`cut_no`，片序小于等于`sample_pieces`时取`sample_length`，否则取`scrap_length`。
- `slice`没有对应的设定数量，`set_number=null`。`cut_no=1`或没有上一刀剩余长度时`shear_length=0`，其余刀次取非负的剩余长度差`max(delta, 0)`。

### 结果写入与运行态提交

- `shear_type`取当前剪刀`type_codes`中判定类型对应的编码；`shear_type_name`固定为`实际关联设备代码_类型小写`，例如`por1_head`或`tr2_tail`。
- `shear_time`取触发帧`receivedAt`；`por/tr`卷号、颜色、剩余长度和最大长度取本次解析出的两侧端点快照。
- 每台设备的 shear runtime 保存最近一次成功入库的触发帧时间。RocketMQ 重投相同消息时，若设备和 `receivedAt` 均相同，则在刀次递增和写表前跳过；幂等标记只在数据库持久化成功后提交。
- 同一帧可以产生多条剪切记录，数据库仓储在一个PostgreSQL事务中批量保存。
- 只有剪切存储开关启用时才同步和提交shear runtime、写入`qm_dc_shear_log`；关闭时仍可计算并返回结果，但不提交运行态和数据库记录。
