# 数字钢卷切片接口

## 接口路径

`POST /api/quality/piece/output`，同步计算并保存单工序切片。

## 入参

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| unitCode | String | 是 | 机组代码，服务端去首尾空白并转大写 |
| outMatNo | String | 是 | 目标出口物料号，原样保留 |
| outMatRepeatProdNo | String | 是 | 出口重复生产次数号，保留字符串及前导零 |
| cellCode | String | 是 | 加工单元代码，按来源值查询，不自动统一大小写 |

```json
{"unitCode":"CP1","outMatNo":"OUT001","outMatRepeatProdNo":"01","cellCode":"CP1001"}
```

目标四字段共同限定物料身份。写入时身份字段最多 50 个 UTF-8 字节。重复生产次数与跟踪生产次数不同。

## 数字钢卷切片流程

### 基础数据初始化

1. `PieceBaseDataServiceImpl.prepare` 在 PostgreSQL 只读可重复读事务中读取配置和物料关系。
2. `PieceBaseDataReader` 要求机组恰有一条有效配置，结果库、单工序结果表非空，配置片长为正数。
3. 从 `qm_biz_parameter` 筛选 digital_coil 库、表名包含 process 或 ironloss、value_type 属于 float/short/int/long/double/byte 的数字参数，按 unique_key 排序。参数非空、名称等必需字段完整；unique_key 忽略大小写不得重复或覆盖固定列。
4. 按机组、加工单元、出口物料号和重复次数查询关系。分卷继续按入口物料号和入口重复次数补齐全部已知兄弟出口；并卷保留目标出口全部入口。
5. 校验 mat_type：0 正常、1 并卷、2 分卷。正常恰一行，并卷至少两入口且出口相同，分卷入口相同且出口不重复。并卷和分卷按 out_mat_sequence_no 数值升序排序，必须从 1 连续且无重复。全部出口长度为正。
6. `PieceStoreService.sync` 调 quality-ts 同步固定列和动态列，发生在在线准备及计算之前。同步会改变表结构，随后计算失败不会撤销此操作。

### 剪切数据准备

`PieceOnlineMatDataServiceImpl.prepare` 按入口 `MatKey` 分组，在 PostgreSQL 独立只读快照内准备。该阶段保留在线运行方向，不反转、不缩放，也不分配到各出口。

- 剪切查询限定 unit_code、cell_code、in_mat_no、in_mat_repeat_prod_no，仅使用 shear_device_code 以小写 tr 开头的记录，不按生产时间窗截断历史。
- shear_type 第三位 1/5/9 分别为切头/分切/切尾，其他值或不完整编码报错。单刀 shear_length 已为米，必须非负，不乘刀数。
- trHead、trTail 分别汇总所有卷取机切头、切尾；无记录为 0。
- 分卷时分切记录要求正 shear_no 和非空 shear_time。按剪切时间、组号排序，再按 shear_no 汇总；首刀时间决定组的出现顺序。
- n 个已知出口对应 n−1 个 trSlice，多出截断、缺少在末尾补 0。正常卷、并卷无分切列表。
- CP1/FCL1 按入口身份、加工单元取最新卷取实绩，排序为 create_time DESC NULLS LAST、id DESC。首位 1 为上卷取、9 为下卷取；缺记录或非法编码失败，不回退旧记录。其他机组不读卷取方式。

### 在线卷长度数据准备

对同一入口全部关系逐行处理：end_prod_time 必须存在；start_prod_time 缺失时用该行结束时间减 2 小时，仅用于计算、不回写。取最早开始和最晚结束，前后各扩展 1 小时。时间按 Asia/Shanghai 解释后，以带时区的瞬时时间绑定查询。

按参数实际 ts_database + ts_table 分组，每个表、每个入口读取一次 head_length 和必要参数列，条件同时包含 coil_no、repeat_prod_no、cell_code、扩展时间窗。MAX(head_length) 在同批内存采样中计算，没有另发逐片 AVG 或 MAX 查询。

- head_length 为 NULL 的行不参与长度和均值；参数 NULL 按字段独立忽略。
- 任一入口的 MAX 缺失或非正数时，整表参数置 NULL，该段不限制有效片数。
- 至少一个有效工艺段才能继续；所有段无效则失败。读取异常、非数字值、NaN 等不是缺长度降级，仍会使取值失败。

### 数字钢卷切片长度生成与换算

`PieceRangeCalculator` 按完整目标成品长度 L 和配置片长 p 生成 ceil(L/p) 片，从 1 编号、从 0 覆盖至 L，末片保留实际长度。剪切量不在分片阶段扣除。

`PieceLengthCalculator.convert` 按每个来源表、入口的在线长度独立换算，正常卷、并卷、分卷公式见[数据映射关系](数字钢卷切片计算过程中的数据映射关系.md)。并卷整片只属于一个入口，接缝向已有片尾对齐；各工艺段的所属入口可能不同。

分卷若遇换算在线起点为负，仅保留此前完整片，不截成半片。有效工艺段及有表检来源共同取连续前缀交集；无有效完整片允许返回 0 并清理旧结果。正常卷、并卷要求完整片数。

### 工艺参数查询与切片取值

`PieceAverageCalculator.average` 按在线位置排序、滑动统计双闭区间 [coilStart, coilEnd] 的算术均值。共享边界采样同时参与相邻片，同位置重复采样均保留，真实 0 有效，NULL 不进入该字段计数。

字段在片内无有效值时，以在线区间中点进行线性插值：取同入口、同表、该字段最近的左右非 NULL 原始采样，两侧各距中点不超过 2 米、左右间距不超过 3 米，边界包含。中点恰有有效样本直接使用；不满足条件返回 NULL，不外推、不跨入口、不沿用前片或已插值结果。运算使用 BigDecimal/DECIMAL128，写入前检查 DOUBLE 有限范围。

### 表面缺陷关联

仅 CP1/FCL1 读取 `digital_coil.qm_defect_surface_check_monthly`。按机组、入口号、原始生产结束月份 YYYY_MM、扩展 ts 范围过滤；不使用扩展后时间取月份，也没有 repeat_prod_no 筛选列。

以入口最大 y_position 作为表检独立在线长度。全部入口无记录时缺陷为 []，不限制片数；并卷部分入口有记录、部分无记录报错。并卷表检使用首个有效工艺段确定的入口贡献边界，再按表检长度换算；其余场景独立换算。

缺陷按成品 [起点, 终点) 关联，对应在线 (coilStart, coilEnd]。共享边界只归后一成品片，成品最终终点不包含。up_down 必须为 0/1。缺陷身份格式、方向标志见[存储细则](数字钢卷切片表存储细则.md)。

### 切片结果写入与返回

完整查询结果校验通过后，先删目标全部旧切片，再按批写新切片。片号必须与计划连续前缀逐片一致，不得跳号或改边界；保存数必须等于实际查询数。返回 `ResultBean<Integer>`：

```json
{"success":true,"msg":"操作成功","data":10}
```

data 为请求目标实际保存片数，分卷允许 0。

### 分卷整组重算

mat_type=2 时，同次请求对关系快照中全部已知出口依次重算，复用同一关系、配置和入口在线数据，不递归调用 output。兄弟出口后续到达时，再次调用会重算更完整的整组，修正早到卷的缩放和偏移。

逐卷隔离计算、保存异常，失败后继续其他出口，整组结束再汇总抛错；已成功卷不会回滚。成功返回只统计请求目标片数，不统计兄弟总片数。重试会重新处理整组。

## 其他管理接口

### 删除切片

`POST /api/quality/piece/delete`：入参与 output 相同，按配置库表和四身份删除，未匹配记录也成功。不联动兄弟卷，不依赖片长、参数配置和物料关系，不重新计算。成功是 `{"success":true,"msg":"操作成功","data":null}`，不能要求 data 必为 true。

### 修改出口身份

`POST /api/quality/piece/update-identity`，以下字段均为必填字符串：

| 参数 | 说明 |
| --- | --- |
| unitCode、cellCode | 限定机组与加工单元，不修改这两个字段 |
| oldOutMatNo、oldOutMatRepeatProdNo | 原出口物料号和重复次数 |
| newOutMatNo、newOutMatRepeatProdNo | 新出口物料号和重复次数 |

只修改单工序结果的两项出口身份，返回实际修改片数。新旧身份相同或旧身份不存在返回 0；新身份已有切片则拒绝。实际修改要求 TDengine 3.x，由 quality-ts 每批最多 100 片处理，失败可能已改部分片，无自动回滚。不修改关系源表或跨工序结果。

### 查询真实采样时间范围

`POST /api/quality/piece/time-range`：四个目标字段加必填 `parameterKeys: List<String>`，列表不得空、重复或包含当前机组未配置的 unique_key。

只准备基础/在线数据和读取原始采样，不同步表结构、不生成或保存切片。复用成品贡献范围的长度换算；按参数请求顺序、入口业务顺序返回，并卷同一参数可有多个入口时间段。返回项：

```json
{"parameterKey":"example_speed","inMatNo":"IN001","inMatRepeatProdNo":"01","startTs":"2026-11-06 08:00:00.000","endTs":"2026-11-06 09:00:00.000"}
```

startTs/endTs 是换算区间内真实采样的最早/最晚 ts，上海时间、毫秒格式，不是扩展查询窗。读取 ts/head_length，不按参数值非空缩短范围；该接口缺有效在线长度或非空贡献区间内无采样时整体失败。

## 错误与事务边界

请求体缺失、格式错误、参数校验以及 IllegalArgumentException 返回 HTTP 400；其他 RuntimeException 返回 HTTP 500，success=false。查询阶段包装的异常可能进入 500，不能仅凭“数据问题”推定 HTTP 400。

编排不包全局事务。先删后写、跨卷重算没有全局锁、原子替换或自动重试；同表产出、删除和身份修改应由调用方串行协调。详细行为以当前服务实现为准。
