# 数字钢卷切片表存储细则

使用 quality-ts 创建表、核对修改列、删除旧结果及写入数据。每机组结果库表由 qm_biz_digital_factory 的 piece_ts_database、piece_ts_table 配置；同一表可包含不同加工单元或物料，不能仅按卷号删除。

## 表结构示例

```sql
-- 结构示意；实际表名来自配置，动态参数列由 unique_key 提供。
CREATE TABLE IF NOT EXISTS `<configured_piece_table>` (
    `ts` TIMESTAMP,                         -- 保存时分配的记录时间，不是生产采样时间
    `unit_code` VARCHAR(50),                -- 当前机组
    `out_mat_no` VARCHAR(50),               -- 当前出口物料号
    `out_mat_repeat_prod_no` VARCHAR(50),    -- 出口重复生产次数，保留前导零
    `cell_code` VARCHAR(50),                -- 当前加工单元
    `piece_length` DOUBLE,                  -- 实际片长，米，正数，末片可较短
    `piece_no` INT,                         -- 当前成品带头到带尾，1 开始连续
    `defect_up_down_reverse` BOOLEAN,       -- true：在线上下表面相对成品反向；false：同向或无表检
    `defect_os_ds_reverse` BOOLEAN,         -- true：在线操作侧/传动侧相对成品互换；false：同向或无表检
    `defect_groups` VARCHAR(16384)          -- 带成品位置的缺陷身份 JSON 数组，无缺陷为 []
    -- , `<unique_key>` DOUBLE              -- 每个有效数字工艺参数一列，可为 NULL
);
```

单工序表不存 out_mat_start/out_mat_end；片段边界由计划及实际片长表达。参数均值及插值统一存 DOUBLE，不按来源 value_type 建不同数值列。每片必须包含所有当前配置参数键，未取得有效值写 NULL。

## 缺陷内容与方向

defect_groups 元素格式：

```text
out_mat_position@@unit_code@@end_month@@ts@@source_id@@in_mat_no
```

位置是当前成品带头起算的米数，HALF_UP 固定三位小数；ts 按 Asia/Shanghai 格式化为 yyyy-MM-dd HH:mm:ss，保留来源实际小数秒，最多九位。数组按不带位置的原身份去重、字典序排列，不保证按位置排列。

成品缺陷关联采用 [起点,终点)，共享边界只归后一片。序列化后的完整 JSON 不能超过 16384 UTF-8 字节，超出直接失败，不截断。

CP1/FCL1 由首个有效工艺段确定本片所属入口，再按该入口卷取方式写方向：上卷取 false/true，下卷取 true/false（依次为上下、操作侧传动侧）。无缺陷记录也保留方向。其他机组均 false/false。原始缺陷身份不因表面翻转改写。

## 表结构同步规则

`PieceStoreService.sync` 调 `POST /manage/table/create`，quality-ts 的 SchemaServiceImpl 处理列式结构：无表创建，缺列新增；未出现在最新配置中的历史列不会自动删除；已有列类型冲突时删列后按新类型重建；同类型字符串宽度不足时扩容，不缩容。

类型冲突重建会影响该列已有数据，且同步发生在计算之前，后续失败不回滚表结构。此规则来自实际 quality-ts，不能以旧文档的“只新增，不删除”推断所有情形均无列删除。

## 保存、时间戳与批量

1. 校验全部片号从 1 连续、实际片长为正且可表示为有限 DOUBLE、参数键完整、缺陷字节容量合法。
2. 读结果表 MAX(ts)，分配起始毫秒为 max(当前系统毫秒, 旧最大 ts 转毫秒 + 1)，先检查整段时间溢出。
3. 按 unit_code + out_mat_no + out_mat_repeat_prod_no + cell_code 删除目标全部旧片，删除失败不写。
4. 为片号 n 分配 start+n−1 毫秒，使用 multiRow=true 调列式保存接口。ts 是存储身份的一部分，不能解释为真实生产时间。
5. HTTP 每批最大片数由 `time-series-storage.singlecell-http-batch-size` 控制，默认 1000，启动校验必须为正整数。

quality-ts 保存路径为 `POST /data/db/{database}/table/{table}/_column`。多行协议中同片全部字段共享时间戳；quality-ts 的 WebSocket 参数绑定负责实际批量提交。

## 删除、重试与并发

删除由 quality-ts 按四字段先查目标时间戳，再按数据库 ms/us/ns 精度，仅合并相邻时间刻度为删除区间，避免误删区间中的其他目标。无匹配记录幂等成功。

先删后写不是原子替换，无锁、无自动重试或回滚。写入失败可留下部分新片；重新整卷产出会再次清理替换。分卷有效结果为空时仍清理目标旧行并返回 0。调用方应避免同表并发产出，以及产出与删除、身份修改互相竞争。
