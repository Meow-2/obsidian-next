# 展示缺陷时如何处理切片量

本主题实际讨论的是横向“切边量”；文件名沿用「切片 2.0」。以下区分后端已保存的语义与界面待定义的转换，避免将米制纵向片段和毫米制横向切边混为一谈。

## 后端已输出什么

| 字段 | 当前含义 | 界面使用注意 |
| --- | --- | --- |
| final_piece_no | 最终成品片号 | 跨工序关联键之一，上游可稀疏；不要重新编号 |
| out_mat_start/end | 当前节点成品片区间，米 | 不可直接当最终卷纵向坐标 |
| defect_groups | 当前成品位置前缀+原缺陷身份的 JSON 数组 | 按单工序/跨工序各自格式解析；不要按数组下标假设缺陷位置顺序 |
| defect_up_down_reverse | true 在线上/下相对最终成品互换，false 同向 | 根据原始缺陷表面标识转换一次 |
| defect_os_ds_reverse | true 在线操作侧/传动侧相对最终成品互换，false 同向 | 根据源横向坐标轴定义选择翻侧 |
| defect_os_trimming | 当前节点成品操作侧累计距离，毫米 | 当前元数据值，未在写入时再按本节点卷取交换 |
| defect_ds_trimming | 当前节点成品传动侧累计距离，毫米 | 与操作侧字段成对使用 |

后端只保存原缺陷身份及纵向成品位置，不将原始缺陷横向坐标直接改写成最终成品横向坐标。原始缺陷具体形状、宽度、横向坐标和图像等仍需从表检来源查询；当前产出接口没有返回这些详情。

## 缺陷身份解析

```text
单工序：位置@@unit_code@@end_month@@ts@@source_id@@in_mat_no
跨工序：位置@@unit_code@@end_month@@in_mat_no@@ts@@source_id
```

位置为当前工序成品带头起算米数，固定三位小数；不是片内距离，也不是最终卷位置。原缺陷以机组、月份、入口、ts、source_id 等联合定位，不能只用 ts 或 source_id。

归属以未舍入位置按成品 [起点,终点) 判定，显示前缀舍入到毫米精度可能看起来落在片边界上；不要再用舍入前缀重新分配片号。共享边界只归后一片，最终终点排除。

## 表面方向处理

源表 up_down=0 表示上表面、1 表示下表面。标志 true 时交换 0/1，false 时保持。横向翻侧同样只根据最终累计标志应用一次；后端已将本节点卷取方向叠加，前端不再重复做同一次卷取翻转。

CP1/FCL1 才查询缺陷，其他节点可有方向值但 defect_groups=[]。无缺陷不能作为方向缺省为 false 的依据；单工序非表检机组才明确写 false/false。

## 切边量与横向坐标的处理约束

后台累计切边先还原成品侧到在线侧、加本单元单侧切边，再按开卷侧别传到入口；当前节点结果只保存当前成品侧的累计量，单位毫米，不乘纵向缩放系数。

界面若以最终成品宽度为视图，需要先明确来源缺陷横向坐标是操作侧起算、传动侧起算还是图像左边起算，来源宽度和缺陷宽度是什么，以及累计量与显示轴如何对应。当前切片代码没有实现这套最终横向裁剪/平移流程。

“翻转后左侧减 defect_os_trimming、右侧减 defect_ds_trimming”只有在显示左/右已经与当前成品操作侧/传动侧统一的前提下才成立；直接套到原始在线或图像坐标可能交换错侧。应先统一单位和侧别，再按对应保留区域裁剪/平移；这是接入设计约束，不是已实现的通用公式。

## 建议验收场景

- 上开/下开与上卷取/下卷取四组合，核对表面和横向只翻转一次。
- 跨多工序累计切边，使用不对称 os/ds 样例验证交换顺序；来源单侧切边本身相同不能替代该检查。
- 同一原缺陷经不同追溯路径或不同最终卷出现时，分别使用当前节点位置和方向。
- 并卷接缝、稀疏片号、纵向共享边界和三位小数显示，核对不重复、不丢片、不重新分配。
- 工序取值部分失败时，按预期树检查结果完整性，不能仅凭产出 success=true 认定所有节点都有结果。
