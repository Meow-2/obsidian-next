# 物料追踪树构建

## 只读接口

quality-mat 的 `QmMatFeignController` 提供下列服务间 HTTP 接口，返回 `R<T>` 信封。这些查询读取血缘和追溯顺序，界面由服务端调用时可直接消费树中的物料关系。

| 接口 | 请求体 | 成功响应的 data |
| --- | --- | --- |
| `POST /feign/mat/cellBlood/tree` | `unitCode`、`outMatNo`、`outMatRepeatProdNo`、`cellCode` | 目标出口的单棵树 |
| `POST /feign/mat/cellBlood/treeByMainProducts` | 主物料档 ID 数组，例如 `[101, 102]` | 以主物料档 ID 为键的对象，值为该档建树结果 |
| `POST /feign/mat/cellBlood/relations` | 与单棵树相同的四字段 | 当前加工单元的完整关系列表 |

若从成品列表进入，可通过 `POST /feign/mat/mainProduct/dynamicQuery` 查询主物料档，再把返回记录的 `id` 传给批量追溯接口。动态查询按 `conditions` 筛选、按 `sorts` 排序。省略 `current` 和 `size` 时返回列表，传入任一参数即返回分页，缺省页码为 1、每页 10 条。

### 按主物料档批量追溯

ID 必须为正整数，去重后按首次出现的顺序处理，空数组返回空对象。服务按主档机组、出口物料号、跟踪号及跟踪生产次数定位候选关系，选加工顺序最大的单元，从关系行取得出口重复生产次数，再复用单棵树流程。批量共用一个 PostgreSQL 只读可重复读快照及一份机组顺序配置。

结果对象仅含成功建树的 ID。缺档、无血缘或该主档的关系校验失败时跳过并记录日志，可按请求 ID 与响应对象的键找出缺项。数据库异常会使整批失败。

跨工序切片产出的 `OCPieceTreeServiceImpl` 使用单棵树接口，随后才准备在线实绩、计算坐标和替换时序结果。

## 输入与节点

根表示按四字段直接指定或由主物料档定位的出口；节点关系保留当前单元完整正常/并卷/分卷记录，上游边由当前入口跟踪身份连接。

- `outMatKey` 包含 `matNo`、`repeatProdNo`。
- `outMatTrackKey` 包含 `matTrackNo`、`prodNo`。两类次数均保留前导零。
- `lastCells` 以当前入口跟踪身份为键，值为上游出口节点。JSON 键格式为“跟踪号 UTF-16 长度 + 冒号 + 跟踪号 + 跟踪生产次数”，例如 `3:A:B01`。可按 `relations` 的业务顺序渲染分支。
- 同一跟踪身份出现在不同加工单元是合法的，不能只用跟踪号作为视图唯一键。
- 分卷 relations 含全部已知兄弟出口，但当前节点 outMatKey 仍只有请求/追溯的那个出口；兄弟关系不等于额外上游分支。
- 汇聚上游沿不同路径生成独立节点，前端若做视觉去重，需要同时保留路径和边关系，不能把可变切片状态合并。

结构字段、空值和生命周期详见[关键数据结构](../跨工序切片/跨工序切片关键数据结构.md)。

## 追溯规则与展示语义

以当前入口跟踪号、跟踪次数查上游候选，按数字工厂机组 `seq × 1000 + 加工单元三位后缀` 选择最近且严格更早的加工单元，完整保留候选出口的并卷关系，再补齐分卷关系。

入口跟踪身份全缺、没有合适前序或到达 YL001 都会终止分支；仅缺一项、身份矛盾、未知单元、歧义上游、异常物料顺序等返回错误。空 lastCells 表示当前实现无法继续追溯，不必然代表现场物料已经完整追溯至原料。

BAF1001、YL001 也属于树结构；前者仅追溯穿透，后者保留实长作为并卷贡献计算依据，两者不写切片结果。界面不要因无切片表记录而直接隐藏这些关系节点。

## 展开为工序卡

1. 从根开始按最终成品向来料方向展开，保留每条父子边和该边关联的入口行。并卷按 `relations` 的入口业务顺序展开，空间摆放顺序以坐标计算的实际贡献段为准；序号和画布左右位置分别表示不同含义。
2. 页面节点标识由根及沿途各入口分支组成，可用复合键数组序列化。同一上游经不同路径出现时可分别展示，也可只渲染一个分组标题并保留下方各路径卡；点击、选区和缺陷状态按路径隔离。
3. 正常关系显示单入口。并卷显示全部已知入口，缺上游树的入口保留名称和追溯终止提示。分卷在目标节点详情中列出兄弟出口，换到兄弟卷需重新定位它的主档或完整加工身份后加载其结果。
4. 同一条路径中连续的 ZRM1 道次可归并为原型的轧机卡。展开的每行保留实际 `cellCode` 和出口跟踪身份，按真实道次排序。收起和展开规则见[界面流程](跨工序追溯界面流程.md)。

## 树与切片结果的关联

界面可按路径标识展示节点和分支。同一跟踪身份可能在不同单元或不同路径出现，节点标识至少需要区分加工单元、出口跟踪身份及路径。保留 YL001、BAF1001 等仅追溯节点。

同时展示切片时，以最终物料号及重复次数定位结果，再按当前 `cell_code`、出口跟踪身份和最终片号匹配。节点查询使用机组、加工单元和出口跟踪身份，路径归属由树提供。存储 `ts` 用于行身份。查询、空结果和局部失败的约定见[界面接口](跨工序追溯界面接口.md)。跨工序产出响应的 `data` 是成功写入总行数，追溯结构从只读接口获取。

## 实现依据

quality-mat 的 `QmMatFeignController`、`MatTraceTreeServiceImpl`、`MatTraceRelationReader`、`MatTraceCellOrder`、`MatTraceTreeNodeFeignDTO`；切片服务的 `MatTraceFeignClient`、`OCPieceTreeServiceImpl`、`OCPieceTreeNode`。追溯规则见 `MatTraceTreeServiceTest` 和 `MatTraceRelationReaderTest`，跨服务字段契约见 `MatTraceContractTest` 和 `MatTraceFeignTest`。
