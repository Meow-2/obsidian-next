# 物料追踪树构建

## 可复用的当前能力

内部服务 `IOCPieceTreeService.build(PieceOutputRequest)` / `OCPieceTreeServiceImpl` 可从最终成品构建完整跨工序物料关系树。只调用此服务会读取 PostgreSQL 关系并校验，不读取在线实绩、不计算切片元数据、不查询工艺表检、不写时序结果。

当前 PieceOutputController 没有公开的树查询 HTTP 接口。界面接入仍需定义只读接口和响应 DTO，不能调用 overcell-output 代替树查询，因为该接口会重算并替换数据。

## 输入与节点

输入为 unitCode、outMatNo、outMatRepeatProdNo、cellCode。根表示请求最终出口；节点关系保留当前单元完整正常/并卷/分卷记录，上游边由当前入口跟踪身份连接。

- 物料号身份用 MatKey(matNo,repeatProdNo)。
- 跨单元连接用 OCPieceMatTrackKey(matTrackNo,prodNo)。
- 同一跟踪身份出现在不同加工单元是合法的，不能只用跟踪号作为视图唯一键。
- 分卷 relations 含全部已知兄弟出口，但当前节点 outMatKey 仍只有请求/追溯的那个出口；兄弟关系不等于额外上游分支。
- 汇聚上游沿不同路径生成独立节点，前端若做视觉去重，需要同时保留路径和边关系，不能把可变切片状态合并。

结构字段、空值和生命周期详见[关键数据结构](../跨工序切片/跨工序切片关键数据结构.md)。

## 追溯规则与展示语义

以当前入口跟踪号、跟踪次数查上游候选，选择路线中最近且严格更早的加工单元，完整保留候选出口的并卷关系，再补齐分卷关系。轧机比较完整三位数道次，不能按最后一位排序。

入口跟踪身份全缺、没有合适前序或到达 YL001 都会终止分支；仅缺一项、身份矛盾、未知单元、歧义上游、异常物料顺序等返回错误。空 lastCells 表示当前实现无法继续追溯，不必然代表现场物料已经完整追溯至原料。

BAF1001、YL001 也属于树结构；前者仅追溯穿透，后者保留实长作为并卷贡献计算依据，两者不写切片结果。界面不要因无切片表记录而直接隐藏这些关系节点。

## 界面接入建议（尚未由当前接口实现）

新增只读适配层时可复用建树服务，以路径或显式节点 ID 输出扁平节点和边，避免直接序列化内部可变计算对象。应呈现机组、加工单元、出口两类身份、关系类型及入口/出口业务顺序，保留仅追溯节点和追溯终点信息。

若同时展示计算结果，需按最终物料身份、当前 cell_code、出口跟踪身份、最终片号匹配，不能将数据库 ts 当作工序时间。当前产出接口仅返回总行数，无法从返回值恢复整棵树或识别全部失败节点。

## 实现依据

`OCPieceTreeServiceImpl`、`PieceBaseDataReader`、`OCPieceCellProfile`、`OCPieceTreeNode`；现有 OCPiecePreparationTest 覆盖道次、分支汇聚、歧义和终点等场景。本页“接入建议”不表示已有前端或 HTTP 接口。
