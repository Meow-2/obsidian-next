# 跨工序追溯界面数据源介绍

## 页面数据和现状

| 界面 | 已有数据与读取依据 | 待接入或缺值行为 |
| --- | --- | --- |
| 材料候选、档案概要 | quality-mat 主物料档，含 `id`、`unitCode`、`outMatNo`、`matTrackNo`、`outMatProdNo`、生产时间、班组、牌号、出口厚宽长及重量等。原值单位厚宽 mm、长度 m、重量 kg | 机组显示名从正式数字工厂配置映射。当前主档字段只适用于该档出口，不能填到每张历史工序卡 |
| 实际工序、上游入口、分卷兄弟 | quality-mat 关系树。关系可提供出口长度和生产时间，树可解析上下游身份 | 逐节点的厚宽、重量、班组等需另取实绩或主档并按真实身份关联；缺值用占位 |
| 各节点米制片区间、片内参数、缺陷引用 | TDengine 跨工序结果表，由数字工厂配置 `piece_ts_database + oc_piece_ts_table` 指定 | 增加业务读接口。表内固定列和参数动态列见[跨工序存储细则](../跨工序切片/数字钢卷跨工序切片表存储细则.md) |
| 母卷范围与焊缝 | 血缘提供关系顺序与上游实长；精确贡献段还需要入口剪切实绩与切片计算 | 初期可用共同片号展示已有区间；无依据的接缝或来料坐标显示缺失，完整贡献段需读服务输出 |
| 缺陷表检 | `digital_coil.qm_defect_surface_check_monthly`；当前切片只读取并关联 CP1/FCL1 的记录，已核实投影含机组、月份、入口、ts、sourceId、yPosition、upDown | 明细类别、严重等级、几何全量字段、拍摄时间语义和图片位置需核对表检源或图片服务，未接字段保留空值；卷级 `defectCode` / `defectClass` 不能替代单缺陷属性 |
| 参数选择、趋势与统计 | `qm_biz_parameter` 提供机组、名称、`unique_key`、来源库表和类型。动态结果列提供逐片数值 | 单位、分组、参数标准、道次规程需正式配置来源。趋势若使用切片值应标明采样粒度为切片，原始采样趋势需单独读取 |
| 参数主题 | HTML 的 `userParamThemes` 与 `activeParamTheme` 通过浏览器 localStorage 演示 | 主题最小字段为主题 ID、名称、应用域、所属机组和有序参数键集合。正式持久化和权限待接入；若先复用本地保存，界面注明仅当前浏览器有效 |
| 完整钢卷档案 | 现有主档、血缘、切片和已查的表检结果可组成摘要 | 原型的档案窗口布局可延续。趋势和档案独立页面如后续接入，沿用当前卷和加工身份传参 |

## 表检来源与展示能力

表检可用性按业务配置与实际数据链路确定。原型只演示常化酸洗单一表检入口；当前切片代码对 CP1、FCL1 关联表检。两个检测工序都有原始记录时，应区分各自实测缺陷与映射自其他工序的提示。缺陷是否为「原料缺陷」或「本工序新增」需要可靠判定字段或另行定义的算法，共同片号或相近位置只能表明存在空间关联。

## 缓存和刷新口径

切片读取以最终卷、节点身份、片号范围和请求参数集合区分缓存；详情按完整来源键批量复用。切换选区和统计方式可复用已加载数据。页面手动刷新重新获取相关读结果。由于切片替换可出现部分写入，刷新后仍应核对每节点的数据覆盖。
