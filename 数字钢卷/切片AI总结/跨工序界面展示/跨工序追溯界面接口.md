# 跨工序追溯界面接口

## 页面加载顺序

```mermaid
flowchart LR
    A[搜索材料候选] --> B[选择主物料档]
    B --> C[读取追溯树]
    C --> D[按最终卷和树节点查询跨工序结果]
    D --> E[批量加载缺陷详情及参数元数据]
    D --> F[米制框选与工序联动]
    E --> F
```

## 可复用的服务间接口

| 用途        | 已有接口                                                         | 使用方式                                                       |
| --------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 材料候选      | `POST /feign/mat/mainProduct/dynamicQuery?current=1&size=20` | 用 `outMatNo LIKE` 查材料号，用 `unitCode EQ` 和生产时间范围收窄；响应为主档分页记录 |
| 已选主档      | `GET /feign/mat/mainProduct/{id}`                            | 提供页面顶部和钢卷档案的主档字段                                           |
| 追溯树       | `POST /feign/mat/cellBlood/treeByMainProducts`               | 单卷详情可传一个 ID；按响应对象中的 ID 查找树，缺键视为该主档未返回追溯结果                  |
| 已知加工身份时查询 | `POST /feign/mat/cellBlood/tree`                             | 使用四字段查询，字段及分支协议见[物料追踪树构建](物料追踪树构建.md)                      |

候选请求示例按北京时间的生产结束时间筛选。日期起始日取 00:00:00，结束日向后一天取 00:00:00 并使用 LT，覆盖结束日最后一秒的小数部分。筛选字段须为 DTO 属性名。

```json
{
  "conditions": [
    {"field":"outMatNo","operator":"LIKE","values":["CA500"]},
    {"field":"unitCode","operator":"EQ","values":["FCL1"]},
    {"field":"endProdTime","operator":"GE","values":["2026-11-01 00:00:00"]},
    {"field":"endProdTime","operator":"LT","values":["2026-11-18 00:00:00"]}
  ],
  "sorts": [{"field":"endProdTime","direction":"DESC"}]
}
```

以上为 quality-mat 内部服务契约。页面通过项目内受鉴权的业务接口访问，由服务端处理 Feign 信封、字段校验和领域异常。主档 Long ID 与来源缺陷 ID 在浏览器侧按字符串承载，服务端转换为内部协议类型；物料及跟踪次数始终使用字符串。

## 首版页面接口

跨工序对齐页面使用 quality-admin 的三个业务接口。材料候选按生产结束时间倒序返回，每页 20 条，主档 ID 以字符串传给页面。

| 方法与路径 | 职责 |
| --- | --- |
| `GET /api/qm/dc/overcell-trace/candidates` | 按可选材料号片段、机组和生产结束日期查主档候选。省略 `material` 时列出当前范围候选，`page` 从 1 开始 |
| `GET /api/qm/dc/overcell-trace/{id}/tree` | 从物料服务查询该主档的追溯树 |
| `POST /api/qm/dc/overcell-trace/{id}/pieces` | 根据 `path`、`after` 和 `parameterKeys` 读取某节点切片。根路径为空数组，首次查询游标为 0，每次最多选 8 个工艺参数 |

quality-admin 根据实际树解析最终卷和节点出口身份，从 PostgreSQL 数字工厂配置定位结果库表，再使用独立的 MyBatis-Plus 会话直读 TDengine。每页最多返回 500 片，`nextAfter` 为空表示读完。CP1、FCL1 的位置查询通过 `defectDetails` 按原表检联合键附加缺陷类型和等级；属性批次查询失败时返回 `defectDetailsFailed`，切片仍可用。

为 quality-admin 配置 `QUALITY_OVERCELL_TDENGINE_URL`、`QUALITY_OVERCELL_TDENGINE_USERNAME` 和 `QUALITY_OVERCELL_TDENGINE_PASSWORD`。URL 使用 `jdbc:TAOS-RS://主机:6041`，数据库账号需能读取配置中的结果表、TDengine 列元数据和 `digital_coil.qm_defect_surface_check_monthly`。切片数据源未配置或查询失败时，页面保留已取得的追溯树并显示节点读取失败。

## 页面只读契约与后续能力

以下是开发用字段与响应语义，路由和是否合并请求由页面接入层确定。

| 能力 | 必需输入 | 返回内容 |
| --- | --- | --- |
| 加载卷及追溯关系 | 主物料档 ID | 主档、根节点、逐路径节点及上游入口边。根的物料号和重复次数用于后续结果查询 |
| 读取跨工序切片结果 | 已解析的最终卷身份、树内节点标识；可附片号集合、参数键列表 | 每节点查询状态、排序后的片号和米制区间、实际片长、缺陷身份及方向切边字段、所需参数值 |
| 批量缺陷详情 | 原缺陷完整联合键集合 | 联合键对应的可用字段及逐项缺失状态。来源、类型、严重等级、几何和图片按实际数据源提供 |
| 工艺参数元数据 | 当前卷涉及的产片机组及可选加工单元 | 参数键、名称和来源；单位、分组、标准范围仅在有正式配置时返回 |
| 母卷贡献边界与精确区间（如接入） | 最终卷和有向入口边；可附当前成品米制区间 | 分支在下游的贡献区间、上游对应区间及使用的实绩口径。复用跨工序坐标计算，包含只追溯节点需要的段数据 |

切片读取按服务端配置确定结果库表与合法列名，按最终卷二字段和节点身份过滤。页面只提交领域身份和参数键。接口返回 `null` 表示参数缺值，合法数值 0 原样传递；片号可稀疏。长卷按节点和片号分页或按范围取数，保证最终片号排序稳定。客户端需区分该批范围内「无记录」和其余数据「尚未加载」。

`/api/quality/piece/overcell-output` 会重算并替换结果，成功返回写入行数。页面筛选、框选和打开档案使用已有数据及只读接口。工艺参数的 `/api/quality/piece/time-range` 返回真实采样时间边界。首版趋势以切片均值为样本。

## 失败和部分数据

- 候选为空、主档失效、未返回追溯树、切片读取失败和某项详情缺失应有各自状态。追溯树加载成功后，即使部分切片查询失败也保留节点和已读结果。
- 同一节点在当前结果范围内若出现重复业务片键，应作为数据冲突提示。读取层不依赖存储 `ts` 选取所谓最新业务值；现有重算采用先删后写，跨表没有统一结果版本。
- 分页、按需加载与刷新使用当前主档和视图条件校验响应归属。统计只在目标范围读取完成后给全量结论，否则提示数据覆盖范围。
