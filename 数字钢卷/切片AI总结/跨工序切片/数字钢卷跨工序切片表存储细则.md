# 数字钢卷跨工序切片表存储细则

通过 quality-ts 建表、列同步、删除和写入；每个产片机组使用 qm_biz_digital_factory 的 piece_ts_database + oc_piece_ts_table。单工序与跨工序结果表不得重合，同一次路径的不同机组不得共用跨工序表。

## 表结构示例

```sql
-- 实际库表来自配置；每机组自己的 unique_key 动态列另行追加。
CREATE TABLE IF NOT EXISTS `<configured_overcell_table>` (
    `ts` TIMESTAMP,                         -- 保存时分配的记录时间，不是生产时间
    `unit_code` VARCHAR(50),                -- 当前节点机组
    `cell_code` VARCHAR(50),                -- 当前节点加工单元，包含轧机道次
    `final_mat_no` VARCHAR(50),             -- 请求最终成品物料号
    `final_mat_repeat_prod_no` VARCHAR(50),  -- 请求最终成品重复生产次数，保留原字符串
    `out_mat_track_no` VARCHAR(50),         -- 当前节点出口跟踪号
    `out_mat_prod_no` VARCHAR(50),           -- 当前节点出口跟踪生产次数，不是重复生产次数
    `final_piece_no` INT,                   -- 最终成品片号，1 开始，上游可稀疏
    `out_mat_start` DOUBLE,                 -- 当前节点成品片起点，米，非负
    `out_mat_end` DOUBLE,                   -- 当前节点成品片终点，米，大于起点
    `piece_length` DOUBLE,                  -- 当前节点实际片长=end-start，米
    `defect_up_down_reverse` BOOLEAN,       -- true：缺陷在线上下相对最终成品反向；false：同向
    `defect_os_ds_reverse` BOOLEAN,         -- true：缺陷在线两侧相对最终成品互换；false：同向
    `defect_os_trimming` DOUBLE,            -- 当前成品操作侧累计切边距离，毫米，非负
    `defect_ds_trimming` DOUBLE,            -- 当前成品传动侧累计切边距离，毫米，非负
    `defect_groups` VARCHAR(16384)          -- 缺陷身份 JSON 数组，无缺陷 []
    -- , `<unique_key>` DOUBLE              -- 当前机组数字参数，允许 NULL
);
```

实际字段不是旧设计中的 final_mat_track_no/final_mat_prod_no 与 out_mat_no/out_mat_repeat_prod_no 组合：最终卷使用物料号身份，当前节点使用出口跟踪身份。表内没有最终跟踪号列，也没有当前节点出口物料号列；应通过关系数据解析当前出口物料。

## 行身份、片号与坐标

业务行校验键为结果库表 + cell_code + 当前出口跟踪联合身份 + final_piece_no，同一次最终卷结果中不允许重复。数据库 ts 则由写入阶段保证每表行时间不同。

final_piece_no 来自最终成品，只在根生成；同片在不同加工单元可出现，上游分支可只拥有片号子集。out_mat_start/end 是该节点成品坐标，不是最终卷坐标；piece_length 是当前映射的实长，不直接按厚比或该机组配置片长填值。

## 动态工艺列与结构同步

每机组读取自己的数字参数集合，所有动态列为 DOUBLE，缺值保留 NULL；参数键必须与配置完全一致，不得覆盖任何固定列。身份字段最多 50 UTF-8 字节，缺陷 JSON 最多 16384 字节，数值需能表示为有限 DOUBLE。

计算前调用 `/manage/table/create` 同步当前路径结构。quality-ts 无表创建，缺列新增；旧多余列不自动删除；类型冲突删列再建；同类型字符串宽度不足只扩容。类型重建可能丢失该列历史值，后续计算失败不回滚结构变更。

## 缺陷身份、方向与切边

元素格式：

```text
out_mat_position@@unit_code@@end_month@@in_mat_no@@ts@@source_id
```

out_mat_position 为当前节点成品带头起算米数，HALF_UP 固定三位小数，既非最终卷位置，也非片内位置。ts 按上海时间保留来源实际小数秒。按不带位置的原始身份去重和字典序排序，不保证位置顺序；同一个原缺陷经不同路径可有不同位置前缀。

只有 CP1/FCL1 查询缺陷，其他产片节点数组为 []，但仍有累计方向和切边结果。两个方向标志表达本节点在线缺陷相对最终成品的变化，已包含当前节点卷取和下游累计变化；不能在界面重复叠加同一卷取变换。

两个 defect_*_trimming 直接继承当前节点元数据，单位毫米，不按纵向长度系数缩放。来源横向坐标与最终卷视图转换还需消费方按统一侧别解释，详见[界面说明](../跨工序界面展示/展示缺陷时如何处理切片量.md)。

## 替换与历史清理

1. 按表组装全部成功节点结果，校验身份、区间、字段集合和缺陷字节容量，检查同表行身份重复。
2. 对每个非空表读取 MAX(ts)，起始毫秒取 max(当前系统时间, 最大历史时间转毫秒+1)，整表检查时间溢出。
3. 从全部有效机组配置及当前路径配置收集跨工序库表，去重并检查不与单工序表交叉。
4. 按 final_mat_no + final_mat_repeat_prod_no 清理全部收集表中该最终卷的历史行，包括本次路径之外、或本次取值失败节点的旧结果。
5. 全部清理成功后按表写入，每表行按 start+行下标分配唯一毫秒；同片号在不同节点不共享时间戳。

清理不额外带最终 unit/cell 条件，因此最终物料号+重复次数应在该结果集合内足以唯一定位最终卷。已从有效配置移除的旧表无法自动发现；改配置前需另行安排旧表处理。

空成功节点列表仍参与整体替换语义。全部节点取值失败时查询服务抛错，不进入清理；部分节点成功则允许替换，失败节点不会保留旧结果。

## 批量协议和失败恢复

HTTP 保存使用 `multiRow=true` 的既有列式接口 `/data/db/{database}/table/{table}/_column`。每表每批最大片数由 `time-series-storage.overcell-http-batch-size` 控制，默认 1000，启动校验正整数，与单工序批量配置独立。

独立删除及重算共用 quality-ts `/data/piece/overcell-delete`，请求携带配置库表列表和最终物料联合身份；表不存在跳过。远端先查目标 ts，按每库时间精度合并相邻刻度删除，避免按宽时间范围误删其他最终卷。

无跨表事务或请求锁，清理中途失败可能只清理部分表，写入中途失败可能只留下部分新行。可重新请求同一最终卷重算；分卷重试会重新处理全部已知兄弟最终卷。同表调用需要串行协调，避免 MAX(ts) 分配冲突或相互删除。

`OCPieceStoreService`、`OCPieceQueryData`、`TimeSeriesStorageConfig`、`PieceStoreFeignClient`；quality-ts 的 `SchemaServiceImpl`、`PieceDeleteService`、`WebSocketPieceWriter`。已有 OCPieceStoreServiceTest、OCPieceManageServiceTest 覆盖身份、冲突、清理范围和失败回执等边界。
