## 两种切片的关系

| 维度 | 单工序 | 跨工序 |
| --- | --- | --- |
| 请求目标 | 某机组、加工单元的出口物料 | 最终成品，并向前追溯各加工单元 |
| 切片编号 | 当前成品从头到尾，从 1 连续编号 | 仅最终成品生成编号，上游保留原号，可稀疏 |
| 片段坐标 | 请求成品坐标，米 | 当前节点成品坐标，米；不是最终成品坐标 |
| 来源长度 | 每个工艺表、入口独立 MAX(head_length) | 跨节点用上游成品实长；节点内取值仍用每个来源的在线长度 |
| 剪切 | 卷取机 tr 前缀设备 | 跨节点用全部设备，节点内取值用卷取机 |
| 结果表 | piece_ts_database + piece_ts_table | piece_ts_database + oc_piece_ts_table |
| 返回 data | 请求目标实际保存片数 | 请求目标在全部成功取值节点保存的总行数 |
| 分卷联动 | 重算同入口全部已知出口 | 仅根节点分卷展开兄弟最终卷，各自独立追溯 |

## 相对原设计的关键校正

1. 所有切片动态工艺列统一为 DOUBLE；value_type 只参与来源参数筛选。
2. 缺陷数组为 VARCHAR(16384)，按 UTF-8 字节限制，元素带当前成品米制位置前缀。
3. quality-ts 表结构同步遇类型冲突会删列重建，同类型字符串只扩容；不能理解为类型冲突只报错。
4. 工艺段缺少任一入口有效长度时，该段参数全置 NULL；所有工艺段均无效才使节点取值失败。SQL、字段类型等异常另行失败。
5. 单工序 CP1/FCL1 必须有合法卷取实绩；跨工序允许对缺失开卷或卷取字段使用加工单元默认值。
6. 跨工序以 final_mat_no + final_mat_repeat_prod_no 定位最终卷，以 out_mat_track_no + out_mat_prod_no 标识当前节点出口。
7. 长度、纵向剪切为米，横向切边为毫米；跨节点按实际成品长度比例映射，没有直接按厚比计算片长。
8. 跨工序节点取值允许部分成功，替换时会清理全部已配置结果表中的目标旧行；成功响应不代表所有节点都已产出。
