# 数字钢卷切片：业务与代码导读

## 1. 先用一句话理解

数字钢卷切片不是物理剪切，而是把钢卷沿长度方向划成连续的虚拟小段，并把过程参数、表面缺陷和上下游物料关系挂到统一的长度坐标上。

它解决的问题是：最终卷上某一段出现质量问题时，系统能够回答“这段钢在每道工序中位于哪里、经历了什么参数、继承了哪些缺陷”。

## 2. 业务术语表

| 术语       | 在本系统中的含义          | 关键字段                                 |
| -------- | ----------------- | ------------------------------------ |
| 钢卷/物料    | 一次生产中被跟踪的带钢对象     | `out_mat_no`、`in_mat_no`             |
| 入口物料     | 当前加工单元投入的钢卷       | `in_mat_*`                           |
| 出口物料     | 当前加工单元产出的钢卷       | `out_mat_*`                          |
| 物料号      | 业务上的钢卷编号          | `out_mat_no`                         |
| 跟踪号      | 跨表、跨工序追踪物料血缘的标识   | `out_mat_track_no`、`in_mat_track_no` |
| 生产次数     | 同一物料重复过机时区分每次生产   | `out_mat_prod_no`、`in_mat_prod_no`   |
| 机组       | 一条生产线或大的生产设备范围    | `unit_code`                          |
| 加工单元     | 机组内更细的处理步骤        | `cell_code`                          |
| 物料血缘     | 入口物料与出口物料之间的转换关系  | `dc_cells_material_blood`            |
| 切片       | 沿长度方向划分的虚拟区间      | 片号、起止长度、`pieceLength`                |
| 切头/切尾    | 从长度方向移除带头或带尾      | `head_cut_length`、`tail_cut_length`  |
| 切边       | 从宽度方向移除左右边部       | `left_trim_width`、`right_trim_width` |
| 开卷/卷取方式  | 决定工序间上下、左右、头尾方向变化 | `por_type`、`tr_type`                 |
| 正常/并卷/分卷 | 一个入口与出口之间的数量关系    | `mat_type`，当前注释约定 0/1/2              |

## 3. 两条核心业务链路

### 3.1 单加工单元切片

```
dc_cells_material_blood
        │ 机组、加工单元、入口/出口卷、长度、累计切头尾
        ▼
数据立方 /szgj/{unitCode}/{cellCode}
        │ 切片长度、设备、时序表、检测仪距离、参数点
        ▼
在线过程时序表 ──→ 按有效长度生成片区间 ──→ 插值并计算每片参数均值
        │
surface_defect ───────────────────────→ 按纵向位置归入片号
        │
        ▼
DcCellsMaterialBloodVO
  ├─ pieceNoPointDataMap
  └─ pieceNoSurfaceDefectMap
```

入口为 `unitCode + outMatNo + outMatProdNo`。控制器查询一条加工单元血缘记录，随后调用 `OutCoilPieceServiceImpl.generateOutCoilPieceData`。

当前实现只把结果放入响应 VO，没有使用已经读取的 `outCoilPieceTable` 配置进行落库。

### 3.2 跨加工单元对齐

```
最终卷 main_product_material
        │ whole_act_path + 最终跟踪号 + 生产次数
        ▼
按 in_mat_track_no 逐级向前追溯
        │
        ├─ 正常路径：A → B → C
        └─ 并卷路径：A1 ┐
                   A2 ├→ B → C
        ▼
按厚度比换算各工序对齐片长
        ▼
按厚度变化累计换算前序切头/切尾量
        ▼
为每个非并卷容器节点执行单加工单元切片
        ▼
返回包含分支的 DcCellsMaterialBloodVO 树
```

代码从最终卷向上游追溯，因此列表第一个元素是靠近最终产品的一侧。`mergePaths` 把多条线性路径压缩成带 `childDcCellsMaterialBloodVOListList` 的树状返回结构。

## 4. 数据来源与职责

| 来源                        | 作用                        | 当前读取位置                     |
| ------------------------- | ------------------------- | -------------------------- |
| `main_product_material`   | 主物料、生产时间窗口、完整实际路径         | 两个 Controller、两个核心 Service |
| `dc_cells_material_blood` | 加工单元内入口/出口血缘、规格、切剪与收放卷方式  | 单卷入口和跨单元追溯                 |
| `dc_units_material_blood` | 机组间血缘                     | 已注入服务，但当前对齐实现没有实际使用        |
| `surface_defect`          | 缺陷纵向/横向位置、表面和类别           | 单卷缺陷归片                     |
| 数据立方元数据                   | 切片长度、输出表、设备及过程点配置         | `CubeServiceImpl`          |
| 在线过程时序表                   | `length` 坐标上的温度、速度、张力等测点值 | 动态 SQL 查询                  |

数据立方路径约定：

```
/szgj/{unitCode}                              机组配置
/szgj/{unitCode}/{cellCode}                   加工单元配置
/szgj/{unitCode}/{cellCode}/{deviceCode}      设备配置
/szgj/{unitCode}/{cellCode}/{deviceCode}/{pointCode} 过程参数点
```

## 5. 100 米钢卷手工推演

假设最终工序 C 的出口卷长 100 m、标准片长 10 m、厚度 1 mm。

| 工序    | 出口厚度 | 当前工序对齐片长             | 本工序切头/尾         |
| ----- | ---- | -------------------- | --------------- |
| C（最终） | 1 mm | 10 m                 | 头 2 m、尾 1 m     |
| B     | 2 mm | `10 × 1 / 2 = 5 m`   | 头 1 m、尾 0 m     |
| A     | 4 mm | `10 × 1 / 4 = 2.5 m` | 头 0.5 m、尾 0.5 m |

对齐片长公式基于厚度变化后的长度延伸：

```
当前工序片长 = 最终工序标准片长 × 最终厚度 / 当前工序厚度
```

当前代码的累计切头尾处理是从最终工序向上游递推。进入更薄的下一节点时，已有切除长度先乘以前后厚度比，再加当前节点自身切除量。

单卷有效区间采用：

```js
effectiveStart = 累计切头量（空值为 0）
effectiveEnd   = 出口卷长度 - 累计切尾量
```

如果有效区间为 `[2, 99]`、片长 10 m，则片起点依次为 2、12、22……92；最后一片不足 10 m。设备的检测仪起止距离差会扩展每片用于取样聚合的结束位置，但片起点仍按 10 m 递增，因此相邻取样窗口可能重叠。

## 6. 单卷代码阅读路线

入口：`OutCoilPieceController.generate`。

1. 从 `dc_cells_material_blood` 取得当前加工单元血缘。
2. 复制到 `DcCellsMaterialBloodVO`。
3. `generateOutCoilPieceData` 读取数据立方配置。
4. 未传对齐片长时使用加工单元自己的 `pieceLength`；跨单元调用时使用换算后的片长。
5. 按累计切头尾算有效长度。
6. 用主物料的开始/结束时间向前后各扩一天查询在线过程表。
7. 为每个设备生成相同片号集合，对设备配置的测点插值、求平均，再合并到片号参数 Map。
8. 查询表检缺陷，根据 `yPos` 和 `height` 计算覆盖片号。
9. 把两个 Map 返回给调用方。
插值方法的意图是：目标长度正好命中采样点时直接取值；落在两点之间时做线性插值；超出原始数据两端时沿用首尾值。每片对一组等距目标点插值后求平均，并保留三位小数。

## 7. 跨单元代码阅读路线

入口：`OverCellPieceAlignController.align`。

1. 查询最终卷 `MainProductMaterial`。
2. 取得最终机组路径 `wholeActPath`，按 `-` 分割。
3. 查询最终机组的加工单元血缘；生产次数大于 1 时查询从 1 到当前次数。
4. 使用上一节点的入口跟踪号继续向上游机组查询。
5. 遇到 `matType=1` 时复制当前路径，展开多条并卷分支。
6. 用最终加工单元配置的片长作为对齐基准。
7. `calculateAlignPieceLength` 按厚度比换算每个节点片长。
8. `calculateHeadTailCutLength` 计算前序累计切头尾量。
9. `mergePaths` 合并重复的公共路径并保留分支。
10. `processAllNestedBloodVO` 递归生成每个实际加工节点的切片数据。

## 8. 调试清单

建议选择一卷拥有完整过程数据、至少两道工序且有一个表面缺陷的钢卷。

```java
  /**  
   * 生成出口卷等长切片数据  
   *  
   * @param  
   * @return  
   */  
  @GetMapping("generate")  
  public R<DcCellsMaterialBloodVO> generate(String unitCode, String outMatNo, String outMatProdNo) {  
    LambdaQueryWrapper<DcCellsMaterialBlood> lambdaQueryWrapper = new LambdaQueryWrapper<>();  
lambdaQueryWrapper.eq(DcCellsMaterialBlood::getUnitCode, unitCode);  
lambdaQueryWrapper.eq(DcCellsMaterialBlood::getOutMatNo, outMatNo);  
lambdaQueryWrapper.eq(DcCellsMaterialBlood::getOutMatProdNo, outMatProdNo);  
DcCellsMaterialBlood dcCellsMaterialBlood = dcCellsMaterialBloodService.getOne(lambdaQueryWrapper);  
  
DcCellsMaterialBloodVO dcCellsMaterialBloodVO = new DcCellsMaterialBloodVO();  
BeanUtils.copyProperties(dcCellsMaterialBlood, dcCellsMaterialBloodVO);  
  
return R.data(outCoilPieceService.generateOutCoilPieceData(dcCellsMaterialBloodVO, null));  
  }

```

### 单卷接口

```http
GET /test/outcoil/piece/generate?unitCode={机组}&outMatNo={物料号}&outMatProdNo={生产次数}
```

断点顺序：

1. Controller 查出的 `DcCellsMaterialBlood` 是否唯一且非空。
2. 数据立方返回的 `pieceLength`、设备、表名和点名。
3. `coilStartLength`、`coilEndLength`。
4. 原始 `DataPoint` 是否按 `length` 有序，参数是否为空。
5. 第一片、中间片、末片的起止位置和聚合结果。
6. 一个缺陷的 `defectStart`、`defectEnd`、起止片号。

### 跨单元接口

```http
GET /test/overcell/piece/align?unitCode={最终机组}&outMatNo={物料号}&outMatProdNo={生产次数}
```

断点顺序：

1. `wholeActPath` 的顺序是否与代码从最终卷向上游追溯的假设一致。
2. 每一层使用的 `inMatTrackNo` 和生产次数集合。
3. 分卷/并卷时生成的路径数量。
4. 每个节点的 `alignPieceLength`。
5. 每个节点的累计切头尾量。
6. 合并后的嵌套结构以及递归切片调用次数。

## 9. 掌握度自检

- 能解释为什么同一片钢在不同工序上的长度可能不同。
- 能区分物料号、跟踪号、生产次数和顺序号。
- 能从一个最终卷定位到上游加工单元血缘记录。
- 能手工算出有效长度、片数、某个缺陷覆盖的片号。
- 能说明插值、平均和检测仪距离窗口分别解决什么问题。
- 能指出设计文档中存在、当前代码中尚未实现的能力。
