# 加工单元内成品卷切片生成接口

## 1. 接口作用

本接口用于在成品卷完成某个加工单元的生产后，按设定切片长度对成品卷进行等长切片，并将每个切片映射到各工艺段对应的在线卷长度区间。

生成过程以成品卷长度坐标为切片基准。系统先获取成品卷总长度及有效长度范围，再按切片长度将成品卷划分为多个连续切片。每个切片首先记录其在成品卷上的起始长度和结束长度，然后根据成品卷与在线卷的物料对应关系、长度换算关系以及卷取方向，将该成品卷长度区间换算为对应的在线卷号、在线卷起始长度和在线卷结束长度。

完成长度对应后，系统再以“在线卷号 + 在线卷起始长度 + 在线卷结束长度”为查询条件，从跟踪服务写入的各工艺段在线卷过程跟踪表中取数。对区间内各工艺参数进行边界插值和平均值计算，最后将成品卷切片区间、对应在线卷区间及工艺参数平均值，按工艺段分表写入 TDengine。

整体顺序如下：

1. 获取成品卷长度和有效长度范围。
2. 以成品卷长度坐标为基准，生成切片序号及成品卷起止长度。
3. 将每个成品卷切片的起止长度换算为对应的在线卷号及在线卷起止长度。
4. 按在线卷号和在线卷起止长度，分别查询各工艺段的在线卷跟踪数据。
5. 计算每个工艺段在该在线卷长度区间内的工艺参数平均值。
6. 按工艺段将切片结果写入对应的 TDengine 切片表。

### 1.1 每条切片记录的内容

- 成品卷号、生产次数号、生产顺序号和加工单元标识。
- 切片序号。
- 切片在成品卷上的起始长度和结束长度。
- 当前工艺段上与该切片对应的在线卷号。
- 切片在在线卷上对应的起始长度和结束长度，用于计算工艺参数。
- 在线卷对应长度区间内，当前工艺段各工艺参数的平均值。

> 本接口暂不处理表面缺陷，不读取缺陷表，也不保存缺陷关联。本文中的“成品卷”指当前加工单元的出口卷，接口不进行跨加工单元切片对齐。

## 2. TDengine 分表存储方式

### 2.1 分表原则

成品卷切片参考跟踪服务中在线卷过程跟踪数据的存储方式：

- 一个加工单元可包含多个工艺段 `segment`，每个段单独对应一张 TDengine 表。
- 工艺参数点位归属于具体工艺段，只在所属段的表中建列和存储。
- 同一成品卷切片在多张段表中各有一条记录，分别保存该段对应的在线卷区间及段内参数平均值。
- 成品卷、生产次数、生产顺序、加工单元、切片和在线卷等标识为固定字段；工艺参数为随段配置动态创建的数值列。

跟踪服务现有过程表命名方式：

```text
{unitCode}_{trackingTypeCode}_{segmentCode}
```

例如 `CP1_process_nof`。成品卷切片表建议沿用相同规则：

```text
{unitCode}_piece_{segmentCode}
```

例如 `CP1_piece_nof`、`CP1_piece_rtf`、`CP1_piece_csf`。`piece` 为建议的切片数据类型代码，最终与跟踪服务表命名配置保持一致。

### 2.2 单段记录示例

假设 `NOF` 段归属参数为 `temperature`、`speed`和 `tension`，则 `CP1_piece_nof` 记录示例如下：

## 3. 接口定义

### 3.1 请求

```http
POST /digital-coil/out-coil-pieces/generate
Content-Type: application/json
```

生成操作会向 TDengine 写入数据，因此不使用 `GET` 请求。

```json
{
  "unitCode": "CP1",
  "cellCode": "CP001",
  "outCoilNo": "QB2401247203",
  "outMatProdNo": 1,
  "outMatSequenceNo": 1,
  "pieceLength": 10.0,
  "regenerate": false
}
```

| 参数                 | 类型      | 必填  | 说明                                       |
| ------------------ | ------- | --- | ---------------------------------------- |
| `unitCode`         | String  | 是   | 机组代码，用于确定跟踪配置及工艺段表                       |
| `cellCode`         | String  | 是   | 加工单元标识                                   |
| `outCoilNo`        | String  | 是   | 成品卷号，对应加工单元出口卷号                          |
| `outMatProdNo`     | Integer | 是   | 成品卷生产次数号                                 |
| `outMatSequenceNo` | Integer | 是   | 成品卷生产顺序号，用于区分并卷、分卷等子卷顺序                  |
| `pieceLength`      | Decimal | 否   | 切片长度，单位 m；不传时使用加工单元默认值，必须大于 0            |
| `regenerate`       | Boolean | 否   | 是否重新生成，默认 `false`；为 `true` 时原子替换各工艺段已有数据 |
|                    |         |     |                                          |

### 3.2 参数校验

- `unitCode + cellCode` 必须对应已配置的加工单元。
- `outCoilNo + outMatProdNo + outMatSequenceNo` 必须能唯一确定成品卷生产记录。
- 必须能查到成品卷对应的在线卷号及物料映射关系。
- 成品卷长度和切片长度必须大于 0。
- 加工单元必须配置至少一个工艺段，每个段必须有稳定唯一的 `segmentCode`。

## 5. 生成处理逻辑

1. 根据 `unitCode + cellCode` 加载加工单元、工艺段和段内参数点位配置。
2. 根据 `outCoilNo + outMatProdNo + outMatSequenceNo` 查询成品卷档案逻辑表及加工单元物料关系逻辑表；这两张表的物理表名待定。
3. 获取成品卷长度，按 `pieceLength` 生成切片序号、成品卷起始长度和结束长度。
4. 查询剪切跟踪逻辑表，获取剪切类型、剪切长度、开卷机/卷取机卷号及剪切时的剩余长度，用于识别切头、切尾、分切和物料边界。
5. 查询开卷卷取跟踪逻辑表，获取开卷方式、卷取方式、对应设备及最大长度，用于判断卷的长度方向和长度基准。
6. 综合加工单元物料关系、剪切跟踪结果、开卷卷取跟踪结果及延伸关系，计算每个切片对应的在线卷号、在线卷起始长度和结束长度。
7. 逐个遍历加工单元的工艺段，按跟踪服务表命名规则定位在线卷过程跟踪表。
8. 按 `online_coil_no` 和在线卷起止长度查询该段原始工艺参数。
9. 对每个参数补齐区间起止边界值，边界无采样点时按长度线性插值，然后对区间内有效值计算平均值。
10. 按工艺段分别建立或更新切片表，将段所属参数作为动态列。
11. 将固定字段、在线卷映射区间及当前段参数平均值写入该段切片表。
12. 校验各段切片序号、切片数量和写入行数，返回生成摘要。

### 5.1 切片边界

除最后一个切片外，成品卷切片采用左闭右开区间：

```text
第 1 片：[0, 10)
第 2 片：[10, 20)
...
最后一片：[1250, 1250.6]
```

```text
piece_count      = ceil(coil_length / piece_length)
out_start_length = (piece_no - 1) * piece_length
out_end_length   = min(piece_no * piece_length, coil_length)
```

如业务要求排除切头、切尾范围，则先确定有效范围，再在有效范围内切片。

### 5.2 工艺参数平均值

对某切片在某工艺段映射出的在线卷区间 `[online_start_length, online_end_length]`：

1. 查询区间内各参数的有效采样点。
2. 区间起点或终点无原始采样点时，使用相邻两点按长度线性插值。
3. 将起点值、区间内采样值和终点值纳入计算。
4. 排除空值后计算算术平均值，建议保留 3 位小数。
5. 某参数在整个区间内都无有效值时写 `null`，不使用 0 代替缺失数据。

本接口暂不读取 `surface_defect` 表，也不写入 `defect_groups` 字段。

## 7. 成品卷切片分段表结构

### 7.1 固定字段

| 字段 | 建议类型 | TDengine Tag | 含义 |
| --- | --- | --- | --- |
| `ts` | TIMESTAMP | 否 | 主时间戳 |
| `out_coil_no` | VARCHAR | 是 | 成品卷号 |
| `out_mat_prod_no` | INT | 是 | 成品卷生产次数号 |
| `out_mat_sequence_no` | INT | 是 | 成品卷生产顺序号 |
| `cell_code` | VARCHAR | 是 | 加工单元标识 |
| `piece_no` | INT | 否 | 成品卷切片序号，从 1 开始；不作为 Tag，避免每个切片拆分出独立子表 |
| `out_start_length` | DOUBLE | 否 | 切片在成品卷上的起始长度，单位 m |
| `out_end_length` | DOUBLE | 否 | 切片在成品卷上的结束长度，单位 m |
| `online_coil_no` | VARCHAR | 是 | 当前工艺段对应的在线卷号 |
| `online_start_length` | DOUBLE | 否 | 在线卷对应起始长度，用于计算工艺参数 |
| `online_end_length` | DOUBLE | 否 | 在线卷对应结束长度，用于计算工艺参数 |

跟踪服务现有过程表将 `coil_no`、`in_mat_prod_no` 和 `pass_no` 标记为 Tag。切片表只将用于定位卷和生产批次的低基数字段标记为 Tag；`piece_no`、长度和工艺参数作为普通数值列。

### 7.2 动态工艺参数列

每张段表只创建当前段配置的参数列：

| 表名              | 工艺段   | 动态列示例                                |
| --------------- | ----- | ------------------------------------ |
| `CP1_piece_nof` | NOF 段 | `temperature`、`speed`、`tension`      |
| `CP1_piece_rtf` | RTF 段 | `furnace_pressure`、`gas_flow`        |
| `CP1_piece_csf` | CSF 段 | `strip_temperature`、`oxygen_content` |

动态列字段名和数据类型直接复用跟踪服务 `SegmentConfig.points` 中的点位短名和数据类型，不使用 `tag1` ~ `tag200` 占位字段。只有数值型工艺参数参与平均值计算；非数值型点位不进行平均计算。

## 8. 特殊情况

### 8.1 一个切片跨越两个在线卷

当并卷、焊缝或切片边界导致一个成品卷切片跨越两个在线卷时，该切片不拆分，整片归属到前一个在线卷。

“前一个在线卷”指按照物料拼接和生产顺序，覆盖该切片起始位置的在线卷。切片记录中的 `online_coil_no` 写前一个在线卷号；`online_start_length` 和 `online_end_length` 按前一个在线卷的有效长度范围截取，不延伸到后一个在线卷。该切片的工艺参数平均值只使用前一个在线卷有效区间内的跟踪数据计算，不查询后一个在线卷的数据。

因此，一个工艺段内的一个成品卷切片始终只写入一条记录，不增加在线卷映射序号，也不进行跨卷参数加权平均。

### 8.2 成品卷由多个在线卷并卷生成

一个成品卷由多个在线卷并卷生成时，先按照物料拼接顺序排列来源在线卷。拼接顺序优先使用生产顺序号；生产顺序号相同或为空时，应使用明确的物料关系顺序字段，不允许依赖数据库默认返回顺序。

处理规则如下：

1. 根据每个来源在线卷的有效长度、切头切尾量和延伸关系，换算其在成品卷长度坐标中的覆盖区间。
2. 将多个来源在线卷的覆盖区间按照拼接顺序首尾相接，形成完整的成品卷长度范围。
3. 成品卷仍按自身长度从 0 开始统一切片，切片序号不因来源在线卷变化而重新编号。
4. 根据切片起始位置落入的来源区间，确定该切片归属的在线卷。
5. 切片完全落在一个来源在线卷内时，将成品卷起止长度换算为该在线卷的起止长度，再查询各工艺段参数。
6. 切片跨越两个来源在线卷的边界时，执行 8.1 的规则：整片归属前一个在线卷，在线卷结束长度截取到前一个在线卷有效范围终点，只使用前一个在线卷的数据计算参数平均值。

并卷后的一个成品卷只生成一套连续的 `piece_no`。每条记录仍只有一个 `online_coil_no`，不把同一切片拆成多条记录。

当前跨工序实现已对 `matType=1` 的并卷关系建立多条追溯分支，并通过 `childDcCellsMaterialBloodVOListList` 返回分支路径。当前实现的分支构建可以保留，但生成成品卷切片时还需要按照上述拼接顺序，把各分支来源在线卷转换为同一个成品卷长度坐标，不能让每个来源卷都从成品卷长度 0 独立生成完整切片。

### 8.3 一个在线卷分卷生成多个成品卷

一个在线卷分卷生成多个成品卷时，每个成品卷都是独立的切片对象。系统应根据成品卷号、生产次数号和生产顺序号分别生成切片，各子卷的 `piece_no` 都从 1 开始。

处理规则如下：

1. 按生产顺序号排列同一在线卷分出的所有成品卷。
2. 根据前序成品卷有效长度、分卷剪切长度及卷间废料长度，计算当前成品卷在原在线卷上的起始偏移量。
3. 当前成品卷的在线卷覆盖区间为“起始偏移量”至“起始偏移量 + 当前成品卷对应的在线有效长度”。
4. 先按当前成品卷自身长度生成切片，再在当前子卷对应的在线卷覆盖区间内换算每个切片的在线卷起止长度。
5. 使用同一个 `online_coil_no` 查询在线卷过程跟踪数据，但各子卷只查询各自对应的在线长度区间。
6. 分卷剪切掉的长度不归属任一成品卷，不得重复计入相邻子卷；相邻子卷在在线卷长度坐标中的有效区间不得重叠。

分卷场景必须保留 `out_mat_sequence_no`，它既用于区分同一在线卷产生的多个成品卷，也用于确定子卷累计偏移顺序。例如在线卷依次分为 A、B、C 三个成品卷，则 B 的在线起始偏移应包含 A 的在线有效长度以及 A、B 之间的分卷剪切或废料长度。

当前跨工序实现能够识别 `matType=2`，但没有针对分卷单独构建路径，也没有计算子卷在原在线卷上的累计起始偏移。因此，现有代码直接按普通关系处理分卷时，可能导致多个子卷都从在线卷长度 0 开始取数。正式实现需要补充上述分卷偏移计算后再生成切片。

## 9. 数据一致性

- 业务唯一键为 `unit_code + cell_code + segment_code + out_coil_no + out_mat_prod_no + out_mat_sequence_no + piece_no`。
- `regenerate=false` 时，已存在完整数据则不重复写入。
- `regenerate=true` 时，先生成各段新数据，通过切片数量、序号和映射覆盖校验后，再原子切换生效版本。
- 任一工艺段建表、计算或写入失败时，整个成品卷切片生成失败，不保留部分段的正式数据。

# 跨工序成品卷切片生成接口

## 1. 接口作用

本接口按照当前跨加工单元切片对齐实现，根据最终工序的成品卷反向追溯其实际加工路径，取得各工序、各加工单元对应的物料关系，并以最终加工单元配置的切片长度为基准，生成整条加工路径上相互对齐的成品卷切片结果。

接口主要完成以下工作：

- 根据最终机组、成品卷号和生产次数号查询主物料信息及实际加工路径。
- 从最终工序开始，沿实际加工路径向前查询各工序、各加工单元的物料关系。
- 处理同一物料重复生产的情况。
- 根据物料关系类型处理正常生产和并卷路径；当前实现对 `matType=1` 的并卷关系构建分支，对 `matType=2` 的分卷关系尚未实现子卷长度偏移处理。
- 以最终加工单元配置的切片长度为标准切片长度。
- 根据各工序出口厚度比例，换算前序工序对应的对齐切片长度。
- 将前序工序切头、切尾量按厚度比例累计换算到后续工序坐标。
- 对路径中的每个非并卷汇总节点调用加工单元内成品卷切片生成逻辑，计算对应工艺参数。
- 将正常路径和并卷分支组织成树形结果返回。

> 当前代码名称为“跨加工单元切片对齐”，实际会根据主物料的 `wholeActPath` 跨机组、跨工序反向追溯，因此本文按业务用途称为“跨工序成品卷切片生成接口”。

## 2. 当前接口定义

### 2.1 请求方式

```http
GET /test/overcell/piece/align
```

当前实现为测试接口，使用 GET 请求并直接返回计算结果。

### 2.2 请求参数

```http
GET /test/overcell/piece/align?unitCode=CP1&outMatNo=QB2401247203&outMatProdNo=1
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `unitCode` | String | 是 | 最终成品卷当前所属机组代码；当前 Controller 使用该字段查询主物料记录 |
| `outMatNo` | String | 是 | 最终工序的成品卷号，即主物料记录中的出口物料号 |
| `outMatProdNo` | String | 是 | 最终成品卷生产次数号；当前实现按字符串保存和查询，随后按整数处理重复生产范围 |

当前 Controller 使用以上三个参数查询唯一的主物料记录，然后将该记录传入跨工序切片对齐服务。当前接口没有单独传入开始工序、结束工序或切片长度；追溯范围取自主物料实际加工路径，标准切片长度取最终加工单元配置。

## 3. 当前处理逻辑

### 3.1 获取最终成品卷和实际加工路径

1. 根据 `unitCode + outMatNo + outMatProdNo` 查询最终成品卷主物料记录。
2. 从主物料记录中取得：
   - `matTrackNo`：最终物料跟踪号。
   - `outMatProdNo`：最终物料生产次数号。
   - `wholeActPath`：实际加工路径，当前实现按 `-` 拆分为机组代码数组。
3. 根据最终机组代码、最终物料跟踪号和生产次数号查询当前机组内的加工单元物料关系。
4. 当生产次数号大于 1 时，当前实现查询从 `1` 到 `outMatProdNo` 的全部生产次数，并按加工单元代码、生产次数号倒序排列。

### 3.2 获取标准切片长度

当前实现取最终机组查询结果中的第一个加工单元作为最终加工单元，通过多维度平台路径读取加工单元配置：

```text
/szgj/{unitCode}/{cellCode}
```

从配置中取得 `pieceLength`，作为最终工序的标准切片长度。

### 3.3 沿实际加工路径反向追溯

当前实现从 `wholeActPath` 的第二个机组开始逐级向前处理：

1. 读取当前路径末端物料关系的 `inMatTrackNo` 和 `inMatProdNo`。
2. 使用该入口物料跟踪号作为前一机组的出口物料跟踪号，查询前一机组的加工单元物料关系。
3. 当入口生产次数号大于 1 时，同样查询从 `1` 到当前生产次数号的全部记录。
4. 将查询结果追加到当前追溯路径，直到处理完 `wholeActPath` 中的全部机组。

### 3.4 并卷路径处理

当前实现通过物料关系字段 `matType` 判断物料关系类型：

| `matType` | 含义 |
| --- | --- |
| `0` | 正常 |
| `1` | 并卷 |
| `2` | 分卷 |
| `3` | 混钢坯 |

当 `matType=1` 时，当前路径被复制为多个分支，每个并卷来源分别追加到一条分支路径。全部路径追溯完成后，`mergePaths` 将公共前缀合并，并把分支路径写入 `childDcCellsMaterialBloodVOListList`，形成树形结果。

### 3.5 对齐切片长度换算

每条追溯路径以列表第一个节点的出口厚度作为基准厚度，以最终加工单元 `pieceLength` 作为标准切片长度。当前实现的换算公式为：

```text
thick_ratio       = base_thickness / current_thickness
align_piece_length = standard_piece_length * thick_ratio
```

换算结果写入每个路径节点的 `alignPieceLength`。如果基准厚度或标准切片长度小于等于 0，当前实现抛出参数异常；当前节点厚度无效时，该节点的 `alignPieceLength` 被设置为 `0.0`。

### 3.6 累计切头、切尾量

当前实现沿每条追溯路径累计前序加工单元的切头、切尾量，并在进入下一节点时按相邻厚度比例换算：

```text
ratio          = previous_thickness / current_thickness
total_head_cut = total_head_cut * ratio + current_head_cut
total_tail_cut = total_tail_cut * ratio + current_tail_cut
```

当前节点处理前的累计值分别写入 `headCutLengthSum` 和 `tailCutLengthSum`，供加工单元内切片生成时确定有效长度范围。

### 3.7 生成各节点切片数据

路径合并为树形结构后，当前实现递归遍历所有节点：

- 普通节点调用加工单元内切片生成逻辑，并传入该节点的 `alignPieceLength`。
- 并卷汇总节点且存在子分支时不直接生成自身切片，继续处理子分支。
- 加工单元内切片生成逻辑查询对应在线卷过程跟踪数据，生成 `pieceNoPointDataMap`。
- 如果存在并卷路径，切片结果保存在各自分支节点中。
