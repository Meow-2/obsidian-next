# 数字钢卷剪切算法 3.0

本文描述当前 `ShearTrackingAlgorithmImpl` 的实际处理逻辑，重点说明剪切类型判断、物料号选取、刀次计数和剪切长度计算。配置示例在 `docs/config/<机组>/shear.json` 下。

## 1. 术语和数据来源

| 名称                 | 含义                                         |
| ------------------ | ------------------------------------------ |
| `shear_device `    | 触发剪切的设备                                    |
| `in_mat_device`    | 被选取为物料的设备                                  |
| `shear_color`      | 当前剪刀配置的 `color_point` 值，经过去除不可见字符和数值规范化    |
| `head`             | 切头                                         |
| `tail`             | 切尾                                         |
| `slice`            | 分切                                         |
| `tail_experience`  | `tail_experience`，与开卷机剩余长度相同单位的切尾经验量       |
| `shear_experience` | `shear_experience`，用于区分同一组剪切和下一组剪切的剩余长度差阈值 |

`shear_device`、`in_mat_device` 的卷号、生产次数、颜色、剩余长度和最大长度来自 `StatusTrackingContext`。剪切触发点和剪刀颜色、光栅、长度、刀数点来自当前帧 `PointSnapshot`。

## 2. 剪切事件识别

每个剪切点独立处理，单点异常不会阻断同一帧其他剪切点。

1. 剪切配置不存在或 `statusContext` 不存在时跳过。
2. 只有剪切信号从 `normal_pos` 离开时才触发剪切事件：上一帧必须等于 `normal_pos`，当前帧必须有效且不等于 `normal_pos`。若触发剪切事件，则继续，否则，更新 runtime 各设备状态，并退出。
3. 读取固定类型或按模式自动判型并确定物料归属
4. runtime 更新
5. 确定物料归属后计算刀次、剪切长度和设定数量，构造 `ShearResult`。
6. 结果成功持久化后才提交 runtime 的幂等时间标记。

`shear_settings.default` 不为空时直接使用该类型，跳过自动判型。

## 3. 剪切类型判断和物料选取

### 3.1 连续线开卷机侧

根据触发的剪刀的 `device_code`, 在 `candidates` 中匹配对应的设备，记为 `shear_device`

1. 若 shear_device.remaining_length <= tail_experience, 剪切类型为切尾 tail，取 in_mat_device = shear_device
2. 若 shear_device.max_length - shear_device.remaining_length <= tail_experience，剪切类型为切头 head，取 in_mat_device = shear_device
3. 若其他，剪切类型为分切 slice，取 in_mat_device = shear_device

### 3.2 连续线卷取机侧（出口剪）

根据触发的剪刀的 `device_codes` , 在 `candidates` 中匹配对应的多个设备，其中 `coli_no` 不为空的，记为 `shear_device`

计算切尾片数边界 tail_limit

   ```text
   front_welder_pieces = welder_pieces / 2  // 整数除法
   tail_limit = front_welder.sample_pieces
             + front_welder.scrap_pieces
             + front_welder_pieces
             + 1
   ```

1. 若 shear_color=shear_device.color_no，剪切类型为分切 slice，若在 `candidates` 中有除 shear_device 外 color_no=shear_color 的 device，则该 device 为 in_mat_device，否则 shear_device 为 in_mat_device
2. 若 shear_color!=shear_device.color_no，取 runtime.shear_device.tail.cut_no。若 cut_no < tail_limit，则剪切类型为切尾 tail，in_mat_device 取 shear_device，取 in_mat_device = shear_device; 若 cut_no >= tail_limit，则剪切类型为切头 head，in_mat_device 取 shear_color 在 candidates 中对应的 device。

### 3.3 非连续线开卷机侧

未配置固定类型时，先比较两侧卷号，再检查开卷机侧光栅：

| 条件                                                                  | 类型      |
| ------------------------------------------------------------------- | ------- |
| `por.coilNo == tr.coilNo` 且 `por.remainingLength < tailExperience`  | `TAIL`  |
| `por.coilNo == tr.coilNo` 且 `por.remainingLength >= tailExperience` | `SLICE` |
| 两侧卷号不同且所有配置光栅均处于各自 `has_coil` 状态                                    | `HEAD`  |
| 两侧卷号不同且至少一个光栅未占位                                                    | `TAIL`  |

## 4. 剪切算法 runtime 记录

剪切算法单个设备的 runtime 结构：

```json
"side" : null,
"device_code" : null,
"device_name" : null,
"coil_no" : null,
"product_no" : null,
"color_no" : null,
"remaining_length" : null,
"max_length" : null,
"HEAD" : {
  "shear_no" : null,
  "cut_no" : null,
  "last_remaining_length" : null
},
"SLICE" : {
  "shear_no" : null,
  "cut_no" : null,
  "last_remaining_length" : null
},
"TAIL" : {
  "shear_no" : null,
  "cut_no" : null,
  "last_remaining_length" : null
}
```

剪切算法 runtime 主要记录各个设备各个 (coli_no+product_no) 的组合下各个剪切类型的 shear_no、cut_no、last_remaining_length，用于后续 shear_no、cut_no 的判断。runtime 按设备分 key 保存，需要持续化到 redis，但程序重启不需要从 redis 中重新读 runtime 到内存。

若没有识别到剪切事件（包括刚启动时没有上一帧消息），则按最新消息更新各设备 runtime ，结束当次流程。其中，当设备的 (coli_no+product_no) 的组合切换时，各个剪切类型的 shear_no、cut_no、last_remaining_length 也会清空为 null。

若识别到剪切事件则根据剪切事件结果，取 runtime 中 in_mat_device 对应剪切类型的 shear_no、cut_no、last_remain_length 更新：

1. 若 shear_no 为 null，初始化 shear_no、cut_no 为 1，last_remaining_length = in_mat_device.remaining_length
2. 若 shear_no 不为空 && last_remain_length - in_mat_device.remaining_length 的绝对值< shear_experience，说明是一次剪切中的不同刀，cut_no+=1，last_remaining_length = in_mat_device.remaining_length
3. 若 shear_no 不为空 && last_remain_length - in_mat_device.remaining_length 的绝对值>= shear_experience，说明是不同的剪切，shear_no +=1，cut_no=1，last_remaining_length = in_mat_device.remaining_length

## 5. 剪切记录生成

已经得到的数据：

1. 触发剪刀的配置 config
2. 剪切类型 shear_type
3. 剪切设备 shear_device
4. 物料选取设备 in_mat_device
5. 剪切 runtime

另外需要计算的数据：

1. shear_type_code、shear_type_name: 取 config.shear.type_codes.shear_type 的值记为 shear_type_code，取 shear_device.code 和 shear_type 用下划线连接，得到 shear_type_name
2. shear_length、set_number: 对于非连续线开卷机/卷取机侧和连续线的开卷机侧，取触发剪刀的配置 config 中对应 shear_type 的 number 和 length，分切当作切头 head 处理。对于连续线的卷取机侧，切尾 tail 使用 front_welder 配置，head 使用 behind_welder 配置，set_number = sample_pieces + scrap_pieces + welder_pieces / 2。切尾 tali 时， 当 cut_no<=sample_pieces+1，shear_length = sample_length，否则 shear_length = scrap_length。切头 head 时，当 cut_no <= scrap_pieces+1,shear_length = scrap_length, 否则 shear_length = sample_length

```json
{
    "unit_code": unit_code,
    "in_mat_no": in_mat_device.coli_no,
    "in_mat_prod_no": in_mat_device.prod_no,
    "shear_type": shear_type_code,
    "shear_type_name": shear_type_name,
    "shear_no": in_mat_device.shear_type.shear_no,
    "cut_no": in_mat_device.shear_type.cut_no,
    "shear_length": shear_length,
    "set_number": set_number,
    "in_mat_device_code": in_mat_device.code,
    "in_mat_device_color_no": in_mat_device.color_no,
    "in_mat_device_remain_length": in_mat_device.remain_length,
    "in_mat_device_max_length": in_mat_device.max_length,
    "shear_device_code": shear_device.code,
    "shear_device_coil_no": shear_device.coil_no,
    "shear_device_color_no": shear_device.color_no,
    "shear_device_remain_length": shear_device.remain_length,
    "shear_device_max_length": shear_device.max_length,
}
```
