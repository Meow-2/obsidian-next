# 数字钢卷剪切算法 3.0

本文描述当前 `ShearTrackingAlgorithmImpl` 的实际处理逻辑，重点说明剪切类型判断、物料号选取、刀次计数和剪切长度计算。配置示例在 `docs/config/<机组>/shear.json` 下。

## 1. 术语和数据来源

| 名称                | 含义                                         |
| ----------------- | ------------------------------------------ |
| `por`             | 开卷机侧物料端点（uncoiler）                         |
| `tr`              | 卷取机侧物料端点（coiler）                           |
| `shearColor`      | 当前剪刀配置的 `color_point` 值，经过去除不可见字符和数值规范化    |
| `HEAD`            | 切头                                         |
| `TAIL`            | 切尾                                         |
| `SLICE`           | 分切                                         |
| `tailExperience`  | `tail_experience`，与开卷机剩余长度相同单位的切尾经验量       |
| `shearExperience` | `shear_experience`，用于区分同一组剪切和下一组剪切的剩余长度差阈值 |

`por`、`tr` 的卷号、生产次数、颜色、剩余长度和最大长度来自 `StatusTrackingContext`。剪切触发点和剪刀颜色、光栅、长度、刀数点来自当前帧 `PointSnapshot`。

## 2. 事件处理流程

每个剪切点独立处理，单点异常不会阻断同一帧其他剪切点。

1. 剪切配置不存在或 `statusContext` 不存在时跳过。
2. 剪切 runtime 记录。
3. 只有剪切信号从 `normal_pos` 离开时才触发事件：上一帧必须等于 `normal_pos`，当前帧必须有效且不等于 `normal_pos`。
4. 读取固定类型或按模式自动判型。
5. 确定物料归属后计算刀次、剪切长度和设定数量，构造 `ShearResult`。
6. 结果成功持久化后才提交 runtime 的幂等时间标记。

`shear_settings.default` 不为空时直接使用该类型，跳过自动判型。

## 3. 剪切算法 runtime 记录

没有上一帧快照时只记录 runtime，不计算剪切。runtime 按设备分 key 保存，需要持续化到 redis，但程序重启不需要从 redis 中重新读 runtime 到内存。

剪切算法 runtime 主要记录各个设备各个 (coli_no+product_no) 的组合下各个剪切类型的 shear_no、cut_no、last_remaining_length，用于后续 shear_no、cut_no 的判断。当设备的 (coli_no+product_no) 的组合切换时，各个剪切类型的 shear_no、cut_no、last_remaining_length 也会清空。

在每次剪切类型判断完成，物料选取完成后，剪切记录生成前，取 runtime 中 in_mat_device 对应剪切类型的 shear_no、cut_no、last_remain_length：

1. 若 shear_no 为 null，初始化 shear_no、cut_no 为 1，last_remaining_length = in_mat_device.remaining_length
2. 若 shear_no 不为空 && last_remain_length - in_mat_device.remaining_length 的绝对值< shear_experience，说明是一次剪切中的不同刀，cut_no+=1，last_remaining_length = in_mat_device.remaining_length
3. 若 shear_no 不为空 && last_remain_length - in_mat_device.remaining_length 的绝对值>= shear_experience，说明是不同的剪切，shear_no +=1，cut_no=1，last_remaining_length = in_mat_device.remaining_length

剪切算法单设备 runtime 结构：

```json
"side" : null,
"device_code" : null,
"device_name" : null,
"coil_no" : null,
"product_no" : null,
"color_no" : null,
"remaining_length" : null,
"max_length" : null,
"HEAD" : {
  "shear_no" : null,
  "cut_no" : null,
  "last_remaining_length" : null
},
"SLICE" : {
  "shear_no" : null,
  "cut_no" : null,
  "last_remaining_length" : null
},
"TAIL" : {
  "shear_no" : null,
  "cut_no" : null,
  "last_remaining_length" : null
}
```

## 3. 剪切类型判断

### 3.1 连续线开卷机侧

根据触发的剪刀的 `device_code`, 在 `candidates` 中匹配对应的设备，记为 `shear_device`

#### 3.1.1 剪切类型

判断切头、切尾、分切类型，在剪刀配置的 `type_codes` 中获取触发剪刀的 `shear_type_code`, 用 `shear_device.code` + `_` + `shear_type` 得到 `shear_type_name`

| 判断顺序 | 条件                                                                        | 类型      |
| ---- | ------------------------------------------------------------------------- | ------- |
| 1    | `shear_device.remainingLength <= tailExperience`                          | `TAIL`  |
| 2    | `shear_device.maxLength - shear_device.remainingLength <= tailExperience` | `HEAD`  |
| 3    | 其他情况                                                                      | `SLICE` |

#### 3.1.2 物料选取

取 `in_mat_device = shear_device`，故 `in_mat_device.coli_no` = `shear_device.coli_no`

### 3.1.3 剪切记录生成

```json
{
    "unit_code": unit_code,
    "in_mat_no": mat_device.coli_no,
    "in_mat_prod_no": mat_device.prod_no,
    "shear_type": shear_type,
    "shear_type_name": shear_type_name,
    "shear_no": runtime.in_mat_device.shearType.shear_no,
    "cut_no": runtime.in_mat_device.shearType.cut_no,
    "set_number": config.in_mat_device_code.shear_settings.shearType.length,
    "in_mat_device_code": in_mat_device.code,
    "in_mat_device_color_no": in_mat_device.color_no,
    "in_mat_device_remain_length": in_mat_device.remain_length,
    "in_mat_device_max_length": in_mat_device.max_length,
    "shear_device_code": shear_device.code,
    "shear_device_coil_no": shear_device.coil_no,
    "shear_device_color_no": shear_device.color_no,
    "shear_device_remain_length": shear_device.remain_length,
    "shear_device_max_length": shear_device.max_length,
}
```

### 3.2 连续线卷取机侧（出口剪）

根据触发的剪刀的 `device_codes` , 在 `candidates` 中匹配对应的多个设备，其中 `coli_no` 不为空的，记为 `shear_device`

#### 3.2.1 剪切类型

当剪刀没有配置固定类型时：

1. 如果 `shearColor == tr.colorNo`，判为 `SLICE`。
2. 如果颜色不相等，先预演本次切尾计数。
3. 计算切尾上限：

   ```text
   frontWelderPieces = welderPieces / 2  // 整数除法
   tailLimit = frontWelder.samplePieces
             + frontWelder.scrapPieces
             + frontWelderPieces
             + 1
   ```

4. 预演得到的 `cutNo <= tailLimit` 时判为 `TAIL`，否则判为 `HEAD`。

出口侧预演计数使用 `por.remainingLength` 计算带钢推进量：

```text
delta = 上一次 por 剩余长度 - 本次 por 剩余长度
```

预演不修改 runtime。最终类型确定后，算法才正式提交对应类型的计数。

出口自动判型要求 `por.colorNo`、`tr.colorNo` 和剪刀颜色均有效。`tr.colorNo` 用于识别分切，`por.remainingLength` 用于推进切尾刀次。

### 3.3 非连续线开卷机侧

未配置固定类型时，先比较两侧卷号，再检查开卷机侧光栅：

|条件 |类型 |
|---|---|
|`por.coilNo == tr.coilNo` 且 `por.remainingLength < tailExperience` |`TAIL` |
|`por.coilNo == tr.coilNo` 且 `por.remainingLength >= tailExperience` |`SLICE` |
|两侧卷号不同且所有配置光栅均处于各自 `has_coil` 状态 |`HEAD` |
|两侧卷号不同且至少一个光栅未占位 |`TAIL` |

### 3.4 非连续线卷取机侧

未配置固定类型时：

|条件 |类型 |
|---|---|
|`por.coilNo == tr.coilNo` |`SLICE` |
|两侧卷号不同且所有配置光栅均占位 |`TAIL` |
|两侧卷号不同且至少一个光栅未占位 |`HEAD` |

## 4. 物料号选取

### 4.1 连续线按剪刀颜色选取

以下场景按剪刀颜色选取物料：

- 连续线开卷机侧的 `HEAD`、`TAIL`、`SLICE`；
- 连续线卷取机侧的 `HEAD`，包括自动判定的切头和配置固定 `default=HEAD` 的切头。

匹配顺序固定为：

1. `shearColor == por.colorNo`：选择 `por`。
2. 否则 `shearColor == tr.colorNo`：选择 `tr`。
3. 两端都不匹配时，遍历本帧 `statusContext.candidates`，只保留 `dataComplete` 不为 `false`、卷号/生产次数/剩余长度完整且颜色匹配的候选。
4. 候选按“卷号 + 生产次数”去重：只有一个物料时选择它；没有候选或存在多个不同物料时跳过事件。

`inMatNo` 和 `inMatNoProdNo` 始终来自同一个选中的物料，避免卷号与生产次数交叉取值。

### 4.2 其他场景的类型归属

连续线卷取机侧的 `TAIL`、`SLICE`，以及非连续线场景，使用剪切侧和类型的默认归属规则：

|剪刀侧 |`HEAD` |`TAIL` |`SLICE` |
|---|---|---|---|
|开卷机侧 |`por` |`tr` |`por` |
|卷取机侧 |`por` |`tr` |`tr` |

连续线卷取机侧的 `HEAD` 是例外：最终按上一节的剪刀颜色规则选取物料。

剪刀颜色点为空或无效时，凡是需要按剪刀颜色选物料的场景都会跳过；颜色值比较前会完成规范化，例如数值 `10` 和字符串 `10.0` 视为相同颜色。

## 5. 刀次和完整剪切计数

每个剪切 runtime 按物料设备和 `HEAD`/`TAIL`/`SLICE` 分别保存：

- `shearNo`：完整剪切组序号；
- `cutNo`：当前完整剪切组内的刀次；
- `lastPorRemainLength`：上一次成功计算时的开卷机剩余长度。

正式计数规则：

```text
delta = lastPorRemainLength - 当前 por.remainingLength
```

- 没有有效历史计数：`shearNo=1`、`cutNo=1`；
- `delta >= 0` 且 `delta < shearExperience`：同一完整剪切，`cutNo + 1`；
- `delta < 0` 或 `delta >= shearExperience`：新完整剪切，`shearNo + 1`、`cutNo=1`。

出口自动判型使用同样的规则预演 `TAIL` 的下一刀，但预演阶段 `apply=false`，不会提前改变 runtime。

## 6. 剪切长度和设定数量

### 6.1 分切

`SLICE` 没有对应设定数量，`setNumber=null`。

- 首刀或没有上一刀剩余长度：`shearLength=0`；
- 其他刀次：`shearLength=max(delta, 0)`。

### 6.2 开卷机侧和非连续线卷取机侧

- `HEAD` 使用 `shear_settings.head.length` 和 `head.number`；
- `TAIL` 使用 `shear_settings.tail.length` 和 `tail.number`。

### 6.3 连续线卷取机侧

- `TAIL` 使用 `front_welder` 配置；
- `HEAD` 使用 `behind_welder` 配置；
- `setNumber = samplePieces + scrapPieces + 本侧焊缝片数`；
- 焊缝总片数前段取整数除以 2，余数分配给后段；
- 配置公共 `length` 时直接读取；未配置时按片序在 `sample_length` 和 `scrap_length` 之间选择。

## 7. 结果、持久化和跳过

结果中的 `shearType` 来自当前剪刀的 `type_codes`，`shearTypeName` 为“实际关联设备代码 + 类型小写”，例如 `por1_head`、`tr2_tail`。结果同时保存本次 `por`、`tr` 的卷号、颜色、剩余长度和最大长度。

剪切存储开关启用时，结果写入 `qm_dc_shear_log`，并提交剪切 runtime。相同设备和相同触发帧 `receivedAt` 的结果在数据库成功持久化后会被标记，RocketMQ 重投时跳过重复事件。

以下情况只跳过当前剪切点：配置或状态上下文缺失、触发沿无效、另一侧 `current` 不存在、两侧物料基础字段不完整、剪刀颜色无效或无法唯一匹配物料、自动切头所需最大长度缺失、光栅或长度设定点无效。
