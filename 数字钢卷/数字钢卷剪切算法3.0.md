# 数字钢卷剪切算法 3.0

本文重构后的数字钢卷剪切 shear 算法的处理逻辑，重点说明剪切类型判断、物料号选取、刀次计数和剪切长度计算。配置示例在 `docs/config/<机组>/shear.json` 下。

## 1. 术语和数据来源

| 名称 | 含义 |
| --- | --- |
| `shear_device` | 触发剪切的设备 |
| `in_mat_device` | 被选取为物料的设备 |
| `shear_color` | 当前剪刀配置的 `color_point` 值，经过去除不可见字符和数值规范化 |
| `head` | 切头 |
| `tail` | 切尾 |
| `slice` | 分切 |
| `tail_experience` | `tail_experience`，与开卷机剩余长度相同单位的切尾经验量 |
| `shear_experience` | `shear_experience`，用于区分同一组剪切和下一组剪切的剩余长度差阈值 |

`shear_device`、`in_mat_device` 的卷号、生产次数、颜色、剩余长度和最大长度来自 `StatusTrackingContext`。剪切触发点和剪刀颜色、光栅、长度、刀数点来自当前帧 `PointSnapshot`。

## 2. 剪切事件识别

每个剪切点独立处理，单点异常不会阻断同一帧其他剪切点。

1. 剪切配置不存在或 `statusContext` 不存在时跳过。
2. 只有剪切信号从 `normal_pos` 离开时才触发剪切事件：上一帧必须等于 `normal_pos`，当前帧必须有效且不等于 `normal_pos`。若触发剪切事件，则继续剪切类型判断和物料选取；否则，更新 runtime 各设备状态，并退出。

## 3. 剪切类型判断和物料选取

`shear_settings.default` 不为空时直接使用该类型，并按下方对应的逻辑选取对应物料。

### 3.1 连续线开卷机侧

根据触发的剪刀的 `device_code`，在 `candidates` 中匹配对应的设备，记为 `shear_device`。

1. 若 `shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切尾 `tail`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `tail` 的 `number` 和 `length`。
2. 若 `shear_device.max_length - shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切头 `head`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。
3. 若其他：
   - 剪切类型为分切 `slice`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 为 `null` ，若 `in_mat_device.cut_no=0`,  `shear_length=0`，否则 `shear_length=in_mat_device.remaining_length`。

### 3.2 连续线卷取机侧（出口剪）

根据触发的剪刀的 `device_codes`，在 `candidates` 中匹配对应的多个设备，其中 `coli_no` 不为空的，记为 `shear_device`。

计算切尾片数边界 `tail_limit`：

```text
front_welder_pieces = welder_pieces / 2  // 整数除法
tail_limit = front_welder.sample_pieces
           + front_welder.scrap_pieces
           + front_welder_pieces
           + 1
```

1. 若 `shear_color = shear_device.color_no`：
   - 剪切类型为分切 `slice`；
   - 若在 `candidates` 中有除 `shear_device` 外 `color_no = shear_color` 的 `device`，则该 `device` 为 `in_mat_device`，否则 `shear_device` 为 `in_mat_device`；
   - `set_number = null`；
   - `shear_length = front_welder.length`。
2. 若 `shear_color != shear_device.color_no`，取 `runtime.shear_device.tail.cut_no`。若 `cut_no < tail_limit`：
   - 剪切类型为切尾 `tail`；
   - `in_mat_device` 取 `shear_device`；
   - 使用 `front_welder` 配置；
   - `set_number = sample_pieces + scrap_pieces + welder_pieces / 2`；
   - `shear_length = front_welder.length`。
3. 若 `shear_color != shear_device.color_no`，取 `runtime.shear_device.tail.cut_no`。若 `cut_no >= tail_limit`：
   - 剪切类型为切头 `head`；
   - `in_mat_device` 取 `shear_color` 在 `candidates` 中对应的 `device`；
   - `head` 使用 `behind_welder` 配置；
   - `set_number = sample_pieces + scrap_pieces + welder_pieces / 2`；
   - `shear_length = behind_welder.length`。

### 3.3 非连续线开卷机侧

1. 若 `shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切尾 `tail`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `tail` 的 `number` 和 `length`。
2. 若 `shear_device.max_length - shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切头 `head`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。
3. 若其他：
   - 剪切类型为分切 `slice`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。

### 3.4 非连续线卷取机侧

根据触发的剪刀的 `device_code`，在 `candidates` 中匹配对应的设备，记为 `shear_device`。

1. 若 `shear_device` 的 `coil_no` 是空的：
   - 剪切类型为切头 `head`；
   - 在开卷机侧的设备中找光栅全部占位的设备，`in_mat_device` 为该设备；
   - 若这样的设备存在多个，或不存在这样的设备，则取 `remain_length` 最小的设备为 `in_mat_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。
2. 若 `shear_device` 的 `coil_no` 非空，且在 `candidates` 中没有第二个与 `shear_device` 的 `coil_no` 相同的设备：
   - 剪切类型为切尾 `tail`；
   - 取 `in_mat_device` 为 `shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `tail` 的 `number` 和 `length`。
3. 若 `shear_device` 的 `coil_no` 非空，且在 `candidates` 中有第二个与 `shear_device` 的 `coil_no` 相同的设备：
   - 剪切类型为分切 `slice`；
   - 取第二个与 `shear_device` 的 `coil_no` 相同的设备为 `in_mat_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。

## 4. 更新各设备剪切算法 runtime 记录

剪切算法单个设备的 runtime 结构：

```json
{
  "side": "uncoiler"/"coiler",
  "device_code": "por2",
  "device_name": "2#正常卷开卷机",
  "last_persisted_trigger_time": "2026-01-01T00:00:00Z",
  "coil_no": "16090008100",
  "product_no": 1,
  "color_no": 0,
  "remaining_length": 0,
  "max_length": 0,
  "HEAD": {
    "shear_no": 0,
    "cut_no": 0,
    "last_remaining_length": 0
  },
  "SLICE": {
    "shear_no": 0,
    "cut_no": 0,
    "last_remaining_length": 0
  },
  "TAIL": {
    "shear_no": 0,
    "cut_no": 0,
    "last_remaining_length": 0
  }
}
```

剪切算法 runtime 主要记录各个设备各个 `(coli_no + product_no)` 的组合下各个剪切类型的 `shear_no`、`cut_no`、`last_remaining_length`，用于后续 `shear_no`、`cut_no` 的判断。runtime 按设备分 key 保存，需要持续化到 redis，但程序重启不需要从 redis 中重新读 runtime 到内存。

其中，`last_persisted_trigger_time` 记录当前剪切设备最近一次已成功写入数据库的触发帧 `receivedAt`，用于剪切消息幂等判断。

当所有剪刀的剪切事件识别完后，若没有识别到剪切事件（包括刚启动时没有上一帧消息），则按最新消息更新各设备 runtime，结束当次流程。其中，当设备的 `(coli_no + product_no)` 的组合切换时，各个剪切类型的 `shear_no`、`cut_no`、`last_remaining_length` 也会清空为 `0`。

若识别到剪切事件，则根据剪切事件结果，取 runtime 中 `in_mat_device` 对应剪切类型的 `shear_no`、`cut_no`、`last_remain_length` 更新：

1. 若 `shear_no` 为 `0`：
   - 初始化 `shear_no`、`cut_no` 为 `1`；
   - `last_remaining_length = in_mat_device.remaining_length`。
2. 若 `shear_no` 不为空且 `|last_remain_length - in_mat_device.remaining_length| < shear_experience`，说明是一次剪切中的不同刀：
   - `cut_no += 1`；
   - `last_remaining_length = in_mat_device.remaining_length`。
3. 若 `shear_no` 不为空且 `|last_remain_length - in_mat_device.remaining_length| >= shear_experience`，说明是不同的剪切：
   - `shear_no += 1`；
   - `cut_no = 1`；
   - `last_remaining_length = in_mat_device.remaining_length`。

- `shear_type_code`：取 `config.shear.type_codes.shear_type` 的值。
- `shear_type_name`：取 `shear_device.code` 和 `shear_type`，用下划线连接。

  "unit_code": unit_code,
  "in_mat_no": in_mat_device.coli_no,
  "in_mat_prod_no": in_mat_device.prod_no,
  "shear_type": shear_type_code,
  "shear_type_name": shear_type_name,
  "shear_no": in_mat_device.shear_type.shear_no,
  "cut_no": in_mat_device.shear_type.cut_no,
  "shear_length": shear_length,
  "set_number": set_number,
  "in_mat_device_code": in_mat_device.code,

  "in_mat_device_remain_length": in_mat_device.remain_length,
  "in_mat_device_max_length": in_mat_device.max_length,

## 6. 幂等设计

剪切消息以“触发剪切的设备 `device_code` + 当前触发帧 `receivedAt`”作为幂等键，幂等时间标记保存在该设备对应的 shear runtime 的 `last_persisted_trigger_time` 字段中。

处理流程如下：

1. 识别到有效剪切触发沿并确定 `shear_device` 后，从该设备的 shear runtime 中读取 `last_persisted_trigger_time`。
2. 若当前触发帧的 `receivedAt` 与 `last_persisted_trigger_time` 相同，说明该设备在该触发帧产生的剪切记录已经成功入库，直接跳过本次事件，不递增 `shear_no`、`cut_no`，也不再次生成或写入剪切记录。
3. 若二者不同，则继续执行原有的剪切类型判断、物料选取、刀次计算和剪切记录生成逻辑。
4. 剪切记录成功写入数据库后，才将结果中的剪切时间写入对应设备 runtime 的 `last_persisted_trigger_time`，并将更新后的 runtime 持久化到 Redis。
5. 若数据库写入失败，不提交本次幂等时间标记，使消息重投时仍可再次处理，避免因提前标记而丢失剪切记录。

该设计用于处理 RocketMQ 重投等导致的同一触发帧重复消费；不同设备即使 `receivedAt` 相同，也分别维护各自的幂等标记，互不影响。剪切存储开关关闭或本次没有生成剪切记录时，不提交幂等时间标记。
