# 数字钢卷剪切算法 3.0

本文重构后的数字钢卷剪切 shear 算法的处理逻辑，重点说明剪切类型判断、物料号选取、刀次计数和剪切长度计算。配置示例在 `docs/config/<机组>/shear.json` 下。

## 1. 术语和数据来源

| 名称 | 含义 |
| --- | --- |
| `shear_device` | 触发剪切的设备 |
| `in_mat_device` | 被选取为物料的设备 |
| `shear_color` | 当前剪刀配置的 `color_point` 值，经过去除首尾不可见字符和数值规范化 |
| `head` | 切头 |
| `tail` | 切尾 |
| `slice` | 分切 |
| `tail_experience` | `tail_experience`，与开卷机剩余长度相同单位的切尾经验量 |
| `shear_experience` | `shear_experience`，用于区分同一组剪切和下一组剪切的剩余长度差阈值 |

`shear_device`、`in_mat_device` 的卷号、生产次数、颜色、剩余长度和最大长度来自 `StatusTrackingContext`。剪切触发点和剪刀颜色、光栅、长度、刀数点来自当前帧 `PointSnapshot`。

设备快照严格按 status 配置中的设备顺序从 `StatusTrackingContext.candidates` 构建。触发设备按剪刀配置的 `device_codes` 顺序匹配；同色、同卷物料按 status 配置顺序选择首个有效候选。多个光栅全占位设备或没有唯一全占位设备时，选择剩余长度最小的有效开卷机；长度相同则保留 status 配置顺序靠前者。只配置单个设备时也可使用 `device_code`。

## 2. 剪切事件识别

每个剪切点独立处理，单点异常不会阻断同一帧其他剪切点。

1. 剪切配置不存在或 `statusContext` 不存在时跳过。
2. 只有剪切信号从 `normal_pos` 离开时才触发剪切事件：上一帧必须等于 `normal_pos`，当前帧必须有效且不等于 `normal_pos`。若触发剪切事件，则继续剪切类型判断和物料选取；否则，更新 runtime 各设备状态，并退出。

## 3. 剪切类型判断和物料选取

`shear_settings.default` 不为空时直接使用该类型，并按下方对应的逻辑选取对应物料。

固定类型只跳过自动判型，不跳过该类型对应的物料选取。连续线出口剪固定为切头或分切时，仍需读取有效的 `color_point`。固定切头按颜色选取首个有效匹配物料；固定分切在颜色等于触发设备颜色时优先选其他同色有效物料，没有其他匹配时回退到触发设备，颜色不等时也归属触发设备。固定切尾归属触发设备，不需要颜色点。

### 3.1 连续线开卷机侧

根据触发的剪刀的 `device_code`，在 `candidates` 中匹配对应的设备，记为 `shear_device`。

1. 若 `shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切尾 `tail`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `tail` 的 `number` 和 `length`。
2. 若 `shear_device.max_length - shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切头 `head`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。
3. 若其他：
   - 剪切类型为分切 `slice`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 为 `null`；
   - 使用更新前 runtime 推演本刀分组：旧计数缺失、`shear_no` 或 `cut_no` 为 `0`，或 `last_remaining_length` 缺失时，按首次分切处理；否则计算 `delta = |in_mat_device.remaining_length - slice.last_remaining_length|`；
   - 若为首次分切，或 `delta >= shear_experience`（新组首刀），则 `shear_length = 0`；否则 `shear_length = delta`。新组首刀会在更新 runtime 前根据长度差判断，不能只用旧 `cut_no = 0` 判断。

### 3.2 连续线卷取机侧（出口剪）

按触发剪刀配置的 `device_codes` 顺序，在 `candidates` 中逐个匹配设备；连续线出口剪只接受 `coil_no` 非空的首个匹配设备，记为 `shear_device`。若配置的是单个 `device_code`，则按单个设备匹配。

计算切尾片数边界 `tail_limit`：

```text
tail_limit = front_welder.sample_pieces
           + front_welder.scrap_pieces
           + (welder_pieces + 1) / 2
```

1. 若 `shear_color = shear_device.color_no`：
   - 剪切类型为分切 `slice`；
   - 按 status 配置顺序查找除 `shear_device` 外、物料信息完整且 `color_no = shear_color` 的首个设备；找到时作为 `in_mat_device`，否则使用 `shear_device`；
   - `set_number = null`；
   - 使用更新前 runtime 推演本刀分组：旧计数缺失、`shear_no` 或 `cut_no` 为 `0`，或 `last_remaining_length` 缺失时，按首次分切处理；否则计算 `delta = |in_mat_device.remaining_length - slice.last_remaining_length|`；
   - 若为首次分切，或 `delta >= shear_experience`（新组首刀），则 `shear_length = 0`；否则 `shear_length = delta`。新组首刀会在更新 runtime 前根据长度差判断，不能只用旧 `cut_no = 0` 判断。
2. 若 `shear_color != shear_device.color_no`，取 `runtime.shear_device.tail.cut_no`。若 `cut_no < tail_limit`：
   - 剪切类型为切尾 `tail`；
   - `in_mat_device` 取 `shear_device`；
   - 使用 `front_welder` 配置；
   - `set_number = sample_pieces + scrap_pieces + (welder_pieces + 1) / 2`；
   - `shear_length` 按以下规则取值：
     - 若 `front_welder.length` 已配置，则直接取 `length`；
     - 否则若 `runtime.in_mat_device.tail.cut_no = 0`，取 `0`；
     - 否则若 `runtime.in_mat_device.tail.cut_no <= sample_pieces + 1`，取 `sample_length`，否则取 `scrap_length`。
3. 若 `shear_color != shear_device.color_no`，取 `runtime.shear_device.tail.cut_no`。若 `cut_no >= tail_limit`：
   - 剪切类型为切头 `head`；
   - `in_mat_device` 取按 status 配置顺序遇到的首个颜色匹配且物料信息完整的设备；
   - `head` 使用 `behind_welder` 配置；
   - `set_number = sample_pieces + scrap_pieces + welder_pieces / 2`；
   - `shear_length` 按以下规则取值：
     - 若 `behind_welder.length` 已配置，则直接取 `length`；
     - 否则若 `runtime.in_mat_device.head.cut_no <= welder_pieces / 2 + scrap_pieces`，取 `scrap_length`，否则取 `sample_length`。

### 3.3 非连续线开卷机侧

1. 若 `shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切尾 `tail`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `tail` 的 `number` 和 `length`。
2. 若 `shear_device.max_length - shear_device.remaining_length <= tail_experience`：
   - 剪切类型为切头 `head`；
   - 取 `in_mat_device = shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。
3. 若其他：
   - 剪切类型为分切 `slice`；
   - 取 `in_mat_device = shear_device`；
   - `set_number = null`；
   - 使用更新前 runtime 推演本刀分组：旧计数缺失、`shear_no` 或 `cut_no` 为 `0`，或 `last_remaining_length` 缺失时，按首次分切处理；否则计算 `delta = |in_mat_device.remaining_length - slice.last_remaining_length|`；

### 3.4 非连续线卷取机侧

根据触发的剪刀的 `device_code`，在 `candidates` 中匹配对应的设备，记为 `shear_device`。

1. 若 `shear_device` 的 `coil_no` 是空的：
   - 剪切类型为切头 `head`；
   - 若开卷机只有一个，则该设备为 `in_mat_device`，否则在入口剪绑定的有效开卷机中找光栅全部占位的设备；若唯一，则该设备为 `in_mat_device`，若这样的设备不唯一或不存在，则取 `remaining_length` 最小的有效开卷机，长度相同时按 status 配置顺序选择；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `head` 的 `number` 和 `length`。
2. 若 `shear_device` 的 `coil_no` 非空，且在 `candidates` 中没有第二个与 `shear_device` 的 `coil_no` 相同的设备：
   - 剪切类型为切尾 `tail`；
   - 取 `in_mat_device` 为 `shear_device`；
   - `set_number` 和 `shear_length` 取触发剪刀的配置中对应 `tail` 的 `number` 和 `length`。
3. 若 `shear_device` 的 `coil_no` 非空，且在 `candidates` 中有另一个物料信息完整、卷号相同的设备：
   - 剪切类型为分切 `slice`；
   - 按 status 配置顺序取除 `shear_device` 外、物料信息有效且卷号相同的首个设备为 `in_mat_device`；
   - `set_number = null`；
   - 使用更新前 runtime 推演分组：旧计数缺失、`shear_no` 或 `cut_no` 为 `0`，或旧剩余长度缺失时按首次分切处理，`shear_length = 0`；否则计算 `delta = |in_mat_device.remaining_length - slice.last_remaining_length|`；若 `delta >= shear_experience`，本刀进入新组且 `shear_length = 0`，否则 `shear_length = delta`。新组判断必须在更新 runtime 前完成，不能仅通过旧 `cut_no = 0` 判断。

## 4. 更新各设备剪切算法 runtime 记录

剪切算法单个设备的 runtime 结构：

```json
{
  "side": "uncoiler" / "coiler",
  "device_code": "por2",
  "device_name": "2#正常卷开卷机",
  "last_persisted_trigger_time": "2026-01-01T00:00:00+08:00",
  "coil_no": "16090008100",
  "product_no": 1,
  "color_no": "0",
  "remaining_length": 0,
  "max_length": 0,
  "HEAD": {
    "shear_no": 0,
    "cut_no": 0,
    "last_remaining_length": 0
  },
  "SLICE": {
    "shear_no": 0,
    "cut_no": 0,
    "last_remaining_length": 0
  },
  "TAIL": {
    "shear_no": 0,
    "cut_no": 0,
    "last_remaining_length": 0
  }
}
```

每个设备只保存一份 runtime，其中的 `coil_no + product_no` 表示该设备当前物料组合；组合变化时清空该设备三类剪切计数，不会并行保留多个历史组合的计数。计数包括各剪切类型的 `shear_no`、`cut_no`、`last_remaining_length`，供后续判组和算刀次使用。runtime 按设备分 key 保存并持续写入 Redis；程序重启后不从 Redis 恢复 runtime 到内存。

其中，`last_persisted_trigger_time` 记录当前剪切设备最近一次已成功写入数据库的触发帧 `receivedAt`，用于剪切消息幂等判断。

当所有剪刀的剪切事件识别完后，若没有生成剪切结果（包括刚启动时没有上一帧消息），则按最新候选更新各设备 runtime，结束当次流程。设备的 `(coil_no + product_no)` 组合变化时，先把 `HEAD`、`SLICE`、`TAIL` 的 `shear_no`、`cut_no`、`last_remaining_length` 清零；最近一次成功入库时间保留。

若生成剪切结果，则计数归属 `in_mat_device`，取其更新前对应剪切类型的 `shear_no`、`cut_no`、`last_remaining_length` 推演下一刀：

1. 若旧计数或 `last_remaining_length` 缺失，或 `shear_no`、`cut_no` 任一为 `0`：
    - 初始化 `shear_no`、`cut_no` 为 `1`；
    - `last_remaining_length = in_mat_device.remaining_length`。
2. 否则计算 `delta = |last_remaining_length - in_mat_device.remaining_length|`。若 `delta < shear_experience`，说明是同一组中的后续刀：
    - `cut_no += 1`；
    - `last_remaining_length = in_mat_device.remaining_length`。
3. 若 `delta >= shear_experience`，说明开始新组：
    - `shear_no += 1`；
    - `cut_no = 1`；
    - `last_remaining_length = in_mat_device.remaining_length`。

分切的 `shear_length` 使用同一推演结果：首次分切或新组首刀为 `0`；同组后续刀为 `delta`。长度判断使用更新前的 runtime，完成推演后才把当前剩余长度写入下一状态。

## 5. 剪切记录生成

- `shear_type`：按当前剪切点的 `type_codes`，根据判定类型取 `head`、`slice` 或 `tail` 对应的配置编码。
- `shear_type_name`：取 `shear_device.device_code` 和剪切逻辑类型的小写名称，用下划线连接。

```json
{
  "unit_code": unit_code,
  "in_mat_no": in_mat_device.coil_no,
  "in_mat_prod_no": in_mat_device.product_no,
  "shear_type": shear_type_code,
  "shear_type_name": shear_device.device_code + "_" + lowercase(shear_kind),
  "shear_time": received_at,
  "shear_no": next_counter.shear_no,
  "cut_no": next_counter.cut_no,
  "shear_length": shear_length,
  "set_number": set_number,
  "in_mat_device_code": in_mat_device.device_code,
  "in_mat_device_color_no": in_mat_device.color_no,
  "in_mat_device_remain_length": in_mat_device.remaining_length,
  "in_mat_device_max_length": in_mat_device.max_length,
  "shear_device_code": shear_device.device_code,
  "shear_device_coil_no": shear_device.coil_no,
  "shear_device_color_no": shear_device.color_no,
  "shear_device_remain_length": shear_device.remaining_length,
  "shear_device_max_length": shear_device.max_length
}
```

剪切结果存储到 `qm_dc_shear_log` 表。`shear_time` 保存触发帧时间，`shear_device_code` 保存触发剪切的设备代码；两者均为表字段，完整字段结构见 [建表脚本](sql/qm_dc_shear_log.sql)。

## 6. 幂等设计

剪切消息以“触发剪切的设备 `device_code` + 当前触发帧 `receivedAt`”作为幂等键，幂等时间标记保存在该设备对应的 shear runtime 的 `last_persisted_trigger_time` 字段中。

处理流程如下：

1. 识别到有效剪切触发沿并确定 `shear_device` 后，从该设备的 shear runtime 中读取 `last_persisted_trigger_time`。
2. 若当前触发帧的 `receivedAt` 与 `last_persisted_trigger_time` 相同，说明该设备在该触发帧产生的剪切记录已经成功入库，直接跳过本次事件，不递增 `shear_no`、`cut_no`，也不再次生成或写入剪切记录。
3. 若二者不同，则继续执行原有的剪切类型判断、物料选取、刀次计算和剪切记录生成逻辑。
4. 同一帧按入口剪配置顺序、再按出口剪配置顺序处理；同一个 `shear_device.device_code` 在本帧只接受第一个成功事件，后续绑定到同一触发设备的剪切点跳过。不同触发设备分别处理。
5. 剪切记录成功写入数据库后，才将结果中的剪切时间写入对应设备 runtime 的 `last_persisted_trigger_time`，并将更新后的 runtime 持久化到 Redis。
6. 若数据库写入失败，不提交本次幂等时间标记，使消息重投时仍可再次处理，避免因提前标记而丢失剪切记录。

该设计用于处理 RocketMQ 重投等导致的同一触发帧重复消费；不同设备即使 `receivedAt` 相同，也分别维护各自的幂等标记，互不影响。剪切存储开关关闭时，算法仍计算并将设备状态、计数更新到 runtime/Redis，但不写数据库且不提交成功入库时间；本次没有生成剪切记录时也不提交幂等时间标记。
