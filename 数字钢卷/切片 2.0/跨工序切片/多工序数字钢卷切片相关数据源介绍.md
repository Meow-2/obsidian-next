# 跨工序数字钢卷切片相关数据源介绍

使用 Mybatis Plus 框架的 LambdaWrapper 读取相关数据库表；无法满足的查询使用 Mybatis XML SQL 完成。查询仅使用有效物料关系记录。

## Postgres quality 数据库

### 物料标识说明

| 标识                                                | 用途                                 |
| ------------------------------------------------- | ---------------------------------- |
| `out_mat_no + out_mat_repeat_prod_no + cell_code` | 定位某加工单元的一次成品卷产出，作为首次查询条件及后续切片对象的标识 |
| `in_mat_track_no + in_mat_prod_no`                | 当前加工单元入口物料的跟踪标识，用于查找上一加工单元的出口      |
| `out_mat_track_no + out_mat_prod_no`              | 加工单元出口物料的跟踪标识，与下一加工单元入口的跟踪标识匹配     |
| `in_mat_no + in_mat_repeat_prod_no + cell_code`   | 定位当前加工单元的入口物料，用于后续关联在线跟踪数据及剪切等实绩   |

 `in_mat_track_prod_no`、`out_mat_track_prod_no` 表示跟踪生产次数号, `in_mat_prod_no`、`out_mat_prod_no`；下文 SQL 使用现有字段名，实际落地需保持字段映射一致。这些跟踪生产次数号与 `in_mat_repeat_prod_no`、`out_mat_repeat_prod_no` 不是同一标识，不能互相替代。

### qm_mat_cells_blood 机组内物料关系表

#### 作用一：从最终成品卷向前追溯全部加工单元的成品卷

首次查询关键字段：`unit_code + cell_code + out_mat_no + out_mat_repeat_prod_no`，分别取自接口入参。

后续查询关键字段：`out_mat_track_no + out_mat_track_prod_no`，分别取当前记录的 `in_mat_track_no + in_mat_track_prod_no`。

查询结果关键字段：`id + backlog_code + unit_code + cell_code + out_mat_no + out_mat_repeat_prod_no + out_mat_track_no + out_mat_track_prod_no + in_mat_no + in_mat_repeat_prod_no + in_mat_track_no + in_mat_track_prod_no + mat_type + out_mat_sequence_no`。

说明：

1. 根据入参查到最终成品卷在指定加工单元的产出关系，将该出口物料加入待切片对象集合。正常一对一关系返回一条记录；并卷可能返回同一出口对应的多条入口关系，必须全部保留。
2. 对当前记录，取入口物料的 `in_mat_track_no + in_mat_track_prod_no`，作为本表下一次查询的 `out_mat_track_no + out_mat_track_prod_no`。命中记录的出口物料即为上一加工单元的成品卷，将该成品卷及其与当前入口的衔接关系保存下来。
3. 对每条新命中的关系继续执行相同查询，直到向前查询无记录，该分支追溯结束。并卷产生多个入口分支时，每个分支都要追溯完成。
4. 后续查询不能固定为入参中的 `unitCode` 或 `cellCode`，否则会漏掉其他机组或加工单元。使用命中记录自身的 `unit_code`、`cell_code` 确定各成品卷所属位置。
5. ZRM1 与其他机组采用同一规则，逐个取得实际衔接的加工单元产出。不能仅根据 `cell_code` 大小推断前后关系，也不能仅按物料号合并不同道次或重复生产记录。
6. 同一出口存在多条入口关系时，保留每条关系；同一产出需要切片一次。待切片对象按 `unit_code + cell_code + out_mat_no + out_mat_repeat_prod_no` 去重，关系记录按主键 `id` 区分。不同分支汇合时可复用已展开结果，但同一路径再次遇到已访问的产出节点时应报告循环关系，避免无限追溯。
7. 首次查询无记录时，应报告最终成品卷关系缺失；后续查询正常返回空集合时才作为追溯终点。查询失败或关系中的跟踪标识不完整时应报告异常，不能当作正常终点。

相邻加工单元的匹配关系：

```text
上一加工单元.out_mat_track_no      = 当前加工单元.in_mat_track_no
上一加工单元.out_mat_track_prod_no = 当前加工单元.in_mat_track_prod_no
```

例如生产顺序为 `加工单元 A → 加工单元 B → 加工单元 C`，从 C 的成品卷开始查询，使用 C 的入口跟踪标识找到 B 的出口，再使用 B 的入口跟踪标识找到 A 的出口。C、B、A 的成品卷分别加入待切片对象集合。

按现有字段名称表示的查询示意：

```sql
-- 首次定位最终成品卷，参数取自接口入参。
SELECT *
FROM qm_mat_cells_blood
WHERE deleted = 0
  AND unit_code = :unitCode
  AND cell_code = :cellCode
  AND out_mat_no = :outMatNo
  AND out_mat_repeat_prod_no = :outMatRepeatProdNo;

-- 向前查找上一加工单元的出口；参数取当前关系记录的入口跟踪标识。
SELECT *
FROM qm_mat_cells_blood
WHERE deleted = 0
  AND out_mat_track_no = :currentInMatTrackNo
  AND out_mat_prod_no = :currentInMatTrackProdNo;
```

追溯查询保留全部命中关系，不使用 `LIMIT 1`。最终成品卷的标识随整次追溯保留，用于将各加工单元的切片结果关联回本次请求。

#### 作用二：提供各成品卷切片所需的完整入口出口关系和跟踪数据定位信息

查询关键字段：`unit_code + cell_code + out_mat_no + out_mat_repeat_prod_no`；分卷关系补查使用 `unit_code + cell_code + in_mat_no + in_mat_repeat_prod_no`。

查询结果关键字段：`out_mat_no + out_mat_repeat_prod_no + in_mat_no + in_mat_repeat_prod_no + cell_code + mat_type + out_mat_sequence_no + out_mat_length + out_mat_thick + out_mat_width + start_prod_time + end_prod_time`。

说明：

1. 对每个待切片成品卷，沿用 [单工序数据源介绍](../单工序切片/数字钢卷切片相关数据源介绍.md) 中本表的完整物料关系准备规则，取得成品长度、入口物料和生产时间等数据。
2. `mat_type = 0` 表示正常产出，入口与出口一对一；`mat_type = 1` 表示并卷，保留全部入口及其拼接顺序，并分别沿入口跟踪标识向前追溯。
3. `mat_type = 2` 表示分卷，追溯沿目标出口对应的入口继续向前；切片计算还需要按该入口物料及加工单元补查全部出口，并按 `out_mat_sequence_no` 数值排序，获得完整分卷关系。补查得到的兄弟子卷用于还原分卷计算关系，不自动加入最终成品卷的上游待切片集合。
4. 每个待切片对象直接使用本表的 `out_mat_repeat_prod_no`，入口在线跟踪数据使用本表的 `in_mat_repeat_prod_no`。后续单工序工艺参数查询以 `coil_no = in_mat_no`、`repeat_prod_no = in_mat_repeat_prod_no`、当前 `cell_code` 和生产时间范围定位数据。
5. `out_mat_length` 单位为米，`out_mat_thick`、`out_mat_width` 单位为毫米；生产时间保持与单工序查询一致的时区口径。重复生产次数号、加工单元或切片计算所需字段缺失时，应报告对应物料的数据不完整。
6. 关系类型、顺序号和长度的校验沿用单工序约定：正常卷、并卷、分卷以外的类型不能直接套用现有计算逻辑；分卷、并卷顺序号按数值排序并检查缺失或重复，成品长度必须为正。

#### 表结构

表结构复用 [单工序数据源介绍](../单工序切片/数字钢卷切片相关数据源介绍.md) 中的 `qm_mat_cells_blood` 定义。本文的跟踪生产次数号设计名称与现有字段名称对应关系见“物料标识说明”。

## 基础数据准备结果

准备完成后得到以下数据，供后续跨工序切片计算使用：

1. 最终成品卷和全部上游加工单元成品卷的待切片集合，每个对象保留 `unit_code + cell_code + out_mat_no + out_mat_repeat_prod_no`。
2. 各加工单元之间的入口出口衔接关系，由入口、出口的跟踪号和跟踪生产次数号匹配确定，保留并卷分支和分支汇合关系。
3. 每个待切片对象的完整正常卷、并卷或分卷关系，以及入口在线跟踪数据定位信息、出口尺寸和生产时间。

后续为集合中的每个成品卷形成切片，并保留其与本次入参最终成品卷的关联。
