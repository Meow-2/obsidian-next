# 数字钢卷切片接口

## 接口路径

POST /api/quality/piece/output

## 入参

| 参数                 | 类型     | 必填  | 说明          |
| ------------------ | ------ | --- | ----------- |
| unitCode           | String | 是   | 机组代码        |
| outMatNo           | String | 是   | 出口物料号       |
| outMatRepeatProdNo | String | 是   | 出口物料重复生产次数号 |
| cellCode           | String | 是   | 加工单元代码      |

## 数字钢卷切片流程

### 基础数据初始化

1. qm_biz_digital_factory 表查询机组对应的数字钢卷切片存储的时序数据库、表名和精度
2. qm_biz_parameter 表查询机组对应的数字钢卷工艺参数的名字、类型、唯一键和存储的时序表和时序库
3. qm_mat_cells_blood 查询加工单元对应的入口出口物料流转情况，需要查询出包含完整分卷/并卷物料流转情况的记录

### 数字钢卷切片长度生成

在加工单元对应的入口出口物料流转情况中，取对应出口物料的长度，根据 qm_biz_digital_factory 配置的精度，对出口物料长度进行切片划分，每个切片有其 piece_no，对应着出口物料的一段长度

### 成品卷长度转在线卷长度前的数据准备

每个切片都对应一段成品卷长度。而成品卷的长度补上**卷取机的头尾剪切量**和**卷取造成的头尾变换**后可以对应到在线卷的长度，从而和跟踪数据的工艺参数和表检仪式缺陷关联上。

表数据使用说明：

1. qm_mat_cells_blood 查询结果的各行 mat_type 值都一样，取第一条的 mat_type 值即可。
2. qm_dc_shear_log 查询结果的剪切实绩中，shear_type 的第三位（shear_type[2]）代表剪切类型，1 代表切头，5 代表分切，9 代表切尾；shear_device_code 以 tr 开头表示卷取机，以 por 开头表示开卷机。
3. qm_dc_coiler_log 中的开卷/卷取方式的第一位（uncoiler_method/coiler_method[0]）为 1 代表上，第一位为 9 代表下。

#### 正常卷产出

 mat_type = 0 时，qm_mat_cells_blood 查询结果只有一条数据。

##### 卷取情况

1. qm_dc_coiler_log 表查询该入口物料的卷取方式

##### 卷取机头尾剪切量

1. qm_dc_shear_log 表查询该入口物料的剪切实绩
2. 计算该条数据的入口物料的在卷取机上的切头量、切尾量，所有卷取机上切头的 shear_length 之和为切头量，所有卷取机上切尾的 shear_length 之和为切尾量

#### 并卷产出

mat_type = 1 时，qm_mat_cells_blood 查询结果有多条入口物料不一样，出口物料一样的数据，out_mat_sequence_no 标明了多个入口物料的焊接顺序

##### 卷取情况

1. qm_dc_coiler_log 表查询多条入口物料的卷取方式

##### 卷取机头尾剪切量

1. qm_dc_shear_log 表查询多条入口物料的剪切实绩
2. 计算每条入口物料在卷取机上的切头量、切尾量，所有卷取机上切头的 shear_length 之和为切头量，所有卷取机上切尾的 shear_length 之和为切尾量

#### 分卷产出

mat_type = 2 时，qm_mat_cells_blood 查询结果有多条入口物料一样，出口物料不一样的数据，out_mat_sequence_no 标明了多个出口卷物料的切分顺序

##### 卷取情况

1. qm_dc_coiler_log 表查询入口物料的卷取方式

##### 卷取机头尾剪切量

1. qm_dc_shear_log 表查询入口物料的剪切实绩
2. 根据入口物料在卷取机上切头、切尾、分切量，所有卷取机上切头的 shear_length 之和为切头量，所有卷取机上切尾的 shear_length 之和为切尾量，对于分切，用 shear_no 区分每一次分切，卷取机上的 一次 shear_no 内的所有 shear_length 之和为分切量
3. 每个出口物料都有自己的切头量和切尾量，入口物料的切头量被算作是第一个出口物料的切头量，入口物料的每一次分切量被算作是下一个出口物料的切头量，入口物料的切尾量被算作是最后一个出口物料的切尾量。qm_dc_shear_log 记录的分切次数和实际分切次数不一定一致，qm_dc_shear_log 多的分切次数不用管，少的分切次数，后面的出口物料的切头量都按 0 算

### 成品卷长度转在线卷长度

在线卷长度减去切头量、减去切尾量，剩余部分经过卷取头尾变换，即可和成品卷长度对应。由此可得成品卷长度和在线卷长度的对应关系：

#### 坐标和函数约定

这里的“长度转换”指长度坐标转换，而不是计算钢卷总长。成品卷坐标 `p` 从成品卷带头开始计量，在线卷坐标 `x` 从对应入口物料的在线带头开始计量，均以米为单位。不同入口物料的在线坐标独立从 0 开始，不能把并卷后的累计坐标直接用来查询单个入口物料。

根据《数字钢卷切片计算过程中的数据映射关系》，上卷取、下卷取的头尾均发生反转，所以长度映射统一为反向映射；两种卷取方式的差别只影响上下、左右坐标。本函数不处理宽度、表面和开卷坐标变换，也不重复补偿开卷机剪切量。前置数据必须与在线跟踪表 `head_length` 使用相同的坐标原点和长度单位。

建议提供以下两个函数，先为目标出口物料构建一次映射，再供其全部切片复用。以下为逻辑签名，不新增 HTTP 接口：

```text
// 校验完整流转关系和前置数据，生成目标成品卷的映射；无数据库写入副作用。
buildLengthMapping(context: LengthMappingContext): OutputLengthMapping

// 将一个成品卷切片转换为一个或多个入口物料的在线区间；越界或映射不完整时抛出业务异常。
mapOutputRange(mapping: OutputLengthMapping,
               outputStart: Decimal, outputEnd: Decimal): List<OnlineRange>
```

`LengthMappingContext` 由前述数据准备步骤生成，其字段约定如下。长度计算使用十进制定点数（Java 可用 `BigDecimal`），不提前按切片精度取整。

| 字段 | 含义与约束 |
| --- | --- |
| unitCode、cellCode | 必填，机组和加工单元标识，限定本次流转及实绩查询范围 |
| outMatNo、outMatRepeatProdNo | 必填，共同标识目标出口物料 |
| matType | 必填，与血缘表一致：`0` 正常、`1` 并卷、`2` 分卷，其他类型不支持 |
| relations | 必填、非空，完整血缘记录；正常一条，并卷包含全部入口，分卷包含全部出口；包含物料联合标识、`out_mat_sequence_no` 和 `out_mat_length` |
| inletFacts | 必填，按 `in_mat_no + in_mat_repeat_prod_no` 唯一关联的入口实绩集合；包含卷取方式、已换算为米的切头量 H、切尾量 T，以及按实际发生顺序排列的分切组长度 C；无对应有效剪切记录时该类剪切量为 0，有记录但长度为空或负数时报错 |
| onlineLengths | 并卷必填，按入口物料联合标识关联的在线总长 N，单位米且大于 0；代表与 `head_length` 同一坐标系下入口物料的完整在线长度，包含卷取机剪掉的头尾，不是原料卷档案长度或成品总长 |

**并卷长度的数据前提**：现有资料的 `out_mat_length` 只定义为出口钢卷长度，不能据此确定每个入口物料的贡献长度；同一出口物料在多条血缘记录中的总长不能重复求和。需要在数据准备阶段补充各入口的 `onlineLengths`。`qm_dc_coiler_log.coiler_max_length` 仅描述为“卷取设备最大长度”，未经确认不能直接等同于 N；工艺参数表的 `MAX(head_length)` 也可能受采样缺失、段差异影响。只有确认某个来源完整且与跟踪坐标一致后，才可用于 N；来源未确定或缺失时返回“并卷入口在线长度缺失”，不得平均分配、按比例缩放或默认填 0。

`OutputLengthMapping` 包含 `unitCode`、`cellCode`、目标出口物料联合标识、成品总长 `outputLength`（十进制数，单位米，大于 0）和按成品坐标升序排列的非空 `segments` 集合；标识字段沿用输入语义。每个映射段的字段如下，全部必填：

| 字段 | 含义与约束 |
| --- | --- |
| inMatNo、inMatRepeatProdNo | 该段所属入口物料的联合标识；查询在线跟踪数据时分别对应 `coil_no`、`repeat_prod_no` |
| outputStart、outputEnd | 该入口在目标成品卷中的覆盖范围，单位米，`0 <= outputStart < outputEnd <= outputLength`；各段连续且不重叠 |
| onlineStart、onlineEnd | 该段对应的在线坐标下界、上界，单位米，`0 <= onlineStart < onlineEnd`；按在线坐标升序存储，方向与成品坐标相反 |

映射段中任意位置的公式为：

```text
x = onlineEnd - (p - outputStart)
```

即成品段起点对应在线段上界，成品段终点对应在线段下界，且两侧段长相等。后续三种情况只负责构建映射段，切片转换复用同一个函数。

#### 正常卷：一个成品卷对应一个在线区间

设成品总长为 `L = out_mat_length`，卷取机切头、切尾量分别为 H、T。其对应在线总长为 `N = H + L + T`，保留的在线范围为 `[H, N - T] = [H, H + L]`。

构建唯一映射段：成品范围 `[0, L]`，在线范围 `[H, H + L]`，归属该入口物料。因此：

```text
x = H + L - p = N - T - p
成品切片 [a, b] 的在线坐标下界 = H + L - b
成品切片 [a, b] 的在线坐标上界 = H + L - a
```

这里 L 已是剪切后的成品长度，不再从 L 中减一次 T；T 用于还原在线总长。若额外提供了可靠的在线总长，应校验其与 `H + L + T` 一致。

#### 分卷：先累计在线偏移，再对目标子卷反向映射

将全部出口物料按 `out_mat_sequence_no` 的**数值**升序排列，表示实际切分先后，得到子卷 `O1 ... On`，各子卷成品长度为 `L1 ... Ln`。不能按字符串排序，也不能按成品带头顺序反排子卷。

按前述准备规则，入口物料切头量归首卷，每个分切组的剪切量归下一卷切头量，入口物料切尾量归末卷：

```text
H1 = 入口切头量 H
Hj = C(j-1)                         (2 <= j <= n)
Tj = 0                              (j < n)
Tn = 入口切尾量 T
```

其中 C 按有效分切记录的 `shear_no` 分组，每组累加所有刀次 `shear_length`，再按组内最早 `shear_time` 升序排列，同一时刻按 `shear_no` 排序。组号不要求连续，不以组号数值作为数组下标；不足 `n - 1` 组时在序列末尾补 0，多出的组忽略。按既有规则只能将缺少的组视作后续分切缺失，不能据此推断中间漏记的位置。

定义子卷卷取前的在线起点偏移 `Bj` 和保留区间起点 `Sj`：

```text
B1 = 0
Bj = sum(Hk + Lk + Tk), k = 1 ... j-1
Sj = Bj + Hj
目标子卷 Oj 的在线保留范围 = [Sj, Sj + Lj]
目标子卷 Oj 的成品坐标 p 对应 x = Sj + Lj - p
```

仅为目标子卷构建一个映射段：成品范围 `[0, Lj]`，在线范围 `[Sj, Sj + Lj]`。所有子卷的在线坐标仍属于同一入口物料，不能在每个子卷重新从 0 计量。入口切尾量只位于最后一个保留区间之后，不进入此前子卷的偏移；分切量已计入下一卷 Hj，不能再计入上一卷 Tj。

#### 并卷：各入口保留段拼接后，整体反转

将全部入口物料按 `out_mat_sequence_no` 的数值升序排列，表示在线经过/焊接先后，得到 `I1 ... In`。设第 i 个入口的在线总长为 Ni，卷取机切头、切尾量为 Hi、Ti，其实际保留贡献长度为：

```text
Di = Ni - Hi - Ti
L = sum(Di)
Ai = sum(Dk), k = 1 ... i-1           // 第 i 个入口在保留带钢拼接坐标中的起点
Pi = L - Ai - Di                     // 第 i 个入口在成品坐标中的起点
```

校验每个 Di 大于 0，且 `sum(Di)` 等于目标成品的 `out_mat_length`。为每个入口建立映射段：成品范围 `[Pi, Pi + Di]`，在线范围 `[Hi, Ni - Ti]`，并按 Pi 升序排列。整体卷取后，成品从头到尾对应 `In ... I1`，不能仅在各入口内部反转却保持焊接顺序不变。

第 i 段的长度转换公式为：

```text
x = (Ni - Ti) - (p - Pi)
```

一个成品切片可能跨越一个或多个焊缝，必须分别与各映射段求交，返回多个入口物料的在线区间，不能只返回一个长度或在不同入口物料之间拼成一个在线区间。

#### 切片转换函数逻辑

`OnlineRange` 保留机组、加工单元和入口物料联合标识，并返回如下字段：

| 字段 | 含义与约束 |
| --- | --- |
| outputStart、outputEnd | 本次切片与映射段交集的成品坐标范围，单位米，便于验证完整覆盖和按成品顺序消费结果 |
| onlineStart、onlineEnd | 对应在线区间的坐标下界、上界，单位米，按升序存储；不代表映射方向变为正向 |
| onlineStartInclusive | 在线下界是否包含：`true` 包含，`false` 不包含；按下述成品边界规则计算 |
| onlineEndInclusive | 在线上界是否包含：`true` 包含，`false` 不包含；本函数固定为 `true` |

成品切片使用左闭右开区间 `[a, b)`，最后一片包含成品终点 L。映射段也采用左闭右开、最后一段含 L 的约定，使焊缝位置归属成品坐标右侧的段。头尾反转后一般对应在线区间 `(onlineStart, onlineEnd]`；仅当交集终点为成品终点 L 时包含在线下界。不能对每个在线结果一律使用左闭右开，否则切片边界处的数据会分配到相邻切片。

```text
function mapOutputRange(mapping, a, b):
    require 0 <= a < b <= mapping.outputLength
    ranges = []
    for segment in mapping.segments:             // 已按成品坐标升序排列
        s = max(a, segment.outputStart)
        e = min(b, segment.outputEnd)
        if s >= e:
            continue                            // 仅边界接触，不产生零长度结果

        ranges.add(OnlineRange(
            unitCode = mapping.unitCode,
            cellCode = mapping.cellCode,
            inMatNo = segment.inMatNo,
            inMatRepeatProdNo = segment.inMatRepeatProdNo,
            outputStart = s,
            outputEnd = e,
            onlineStart = segment.onlineEnd - (e - segment.outputStart),
            onlineEnd = segment.onlineEnd - (s - segment.outputStart),
            onlineStartInclusive = (e == mapping.outputLength),
            onlineEndInclusive = true
        ))

    require sum(range.onlineEnd - range.onlineStart) == b - a
    return ranges                               // 非空，保持成品坐标顺序，允许多个入口
```

调用方按切片序号 `piece_no` 从 1 开始构造 `a = (piece_no - 1) * pieceLength`、`b = min(piece_no * pieceLength, L)`，每个返回区间使用其入口物料联合标识和 `cell_code`，结合对应工艺段的时间范围查询 `head_length`。同一切片跨入口物料时，后续聚合仍属于原切片，不重新编号。表面缺陷仅在确认 `y_position` 与该在线坐标一致后复用此区间；缺陷表缺少重复生产号，需用入口物料和时间范围隔离不同生产记录。

#### 校验与算例

构建映射时必须校验目标出口唯一、关系类型一致、完整血缘不缺失、长度合法、卷取方式首位为 `1` 或 `9`。并卷/分卷的顺序号必须可转为数值且不重复；存在缺号时不能仅凭序号连续性判断血缘完整。重复查询行按业务标识识别，冲突值应报错，不能通过累加长度掩盖重复。分卷实绩不足补 0、多余忽略仅限前述已明确的分切组规则，其他必需数据缺失不采用该降级方式。

映射应覆盖 `[0, L]`，成品各段连续且不重叠，每段在线长度与成品长度相等；正常和分卷的成品长度均须大于 0。并卷贡献总长与出口长度不一致时返回数据不一致错误，不自动拉伸映射。若实际长度来源存在测量误差，需另行确认容差和修正口径，本设计默认十进制精确校验。

以下区间用括号区分端点是否包含，所有长度单位为米：

| 场景 | 输入及映射计算 | 切片转换结果 |
| --- | --- | --- |
| 正常卷 | `L=100，H=2，T=3`，推导 `N=105`，在线保留 `[2,102]` | 成品 `[0,10)` → 入口 `(92,102]`；末片 `[90,100]` → `[2,12]` |
| 分卷第二卷 | `L1=40，L2=60，H=2，C1=1，T=3`，第二卷 `B2=42，S2=43`，在线保留 `[43,103]` | 第二卷成品 `[0,10)` → 同一入口 `(93,103]`，不能错误地映射成 `(50,60]` |
| 分卷缺少分切记录 | 三卷长度均为 20，`H=2`，只有 `C1=1`，补 `C2=0`；第三卷 `S3=43` | 第三卷成品 `[0,5)` → 同一入口 `(58,63]`；额外分切组不计入偏移 |
| 并卷跨焊缝 | I1：`N1=45，H1=2，T1=3，D1=40`；I2：`N2=64，H2=1，T2=3，D2=60`；成品 `L=100`，先对应 I2 的 `[0,60)`，后对应 I1 的 `[60,100]` | 成品 `[55,65)` → I2 的 `(1,6]` 和 I1 的 `(37,42]`，长度之和为 10；恰在 `p=60` 的点归 I1，映射到 `x=42` |
| 并卷长度不一致 | 沿用上一例入口数据，但出口 `L=101` | 构建映射失败，不产生切片结果 |
| 范围或元数据异常 | `a=b`、`b>L`、顺序重复、未知卷取方式、并卷缺少 Ni | 返回对应业务错误，不返回空列表或伪造区间 |

上述正常、分卷和并卷算例分别使用上卷取、下卷取时，长度结果应完全一致。实现时还应验证跨多个焊缝、恰好落在焊缝的起止边界、全卷范围、最后不足一个切片精度的尾片、分切组多余或不足，以及同物料号不同重复生产次数的隔离行为。
