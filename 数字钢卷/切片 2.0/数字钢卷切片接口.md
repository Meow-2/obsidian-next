# 数字钢卷切片接口

## 接口路径

POST /api/quality/piece/output

## 入参

| 参数                 | 类型     | 必填  | 说明          |
| ------------------ | ------ | --- | ----------- |
| unitCode           | String | 是   | 机组代码        |
| outMatNo           | String | 是   | 出口物料号       |
| outMatRepeatProdNo | String | 是   | 出口物料重复生产次数号 |
| cellCode           | String | 是   | 加工单元代码      |

## 数字钢卷切片流程

#### 变量命名与入参

所有长度单位统一为米，位置均为到各自带头的距离。

`out_mat_sequence_no` 为从 1 开始的业务顺序号；物料数组按该字段数值升序排列后，下标统一从 0 开始。数组下标统一使用 `i`，在各自场景中表示并卷入口、分卷出口或沿在线运行方向排列的分切记录下标。分卷与并卷不会同时出现。公式中的数组切片 `[0:i]` 表示下标从 0 到 i（不含 i）的元素，`[0:i + 1]` 表示下标从 0 到 i（含 i）的元素，空切片求和为 0。

| 变量                        | 含义                                                                       |
| ------------------------- | ------------------------------------------------------------------------ |
| `outMatLength`            | 成品卷长度                                                                    |
| `outMatPos`               | 成品卷位置，到成品带头的距离                                                           |
| `coilLength`              | 当前工艺段入口在线卷的完整长度，取该段工艺参数表的最大 `head_length`，单位米；并卷按入口物料保存为 `coilLength[i]` |
| `coilPos`                 | 在线卷位置，到在线带头的距离                                                           |
| `trHead`                  | 在线卷在卷取机上的切头总量，按在线运行方向记录；正常卷、分卷为单值，并卷按入口物料保存为 `trHead[i]`                 |
| `trTail`                  | 在线卷在卷取机上的切尾总量，按在线运行方向记录；正常卷、分卷为单值，并卷按入口物料保存为 `trTail[i]`                 |
| `trSlice[i]`              | 同一入口在线卷在卷取机上、数组下标为 i 的分切汇总量，按在线运行顺序排列，下标从 0 开始；无分切记录时为空数组                |
| `lengthScale`             | 补齐剪切量后的完整长度转实际在线长度的缩放系数；并卷按入口分别计算为 `lengthScale[i]`                                                  |
| `outMatStart`、`outMatEnd` | 切片在目标成品卷中的起点、终点                                                          |
| `coilStart`、`coilEnd`     | 换算区间在对应入口在线卷中的起点、终点                                                      |

### 基础数据初始化

1. qm_biz_digital_factory 表查询机组对应的数字钢卷切片存储的时序数据库、表名和精度
2. qm_biz_parameter 表查询机组对应的数字钢卷工艺参数的名字、类型、唯一键和存储的时序表和时序库
3. qm_mat_cells_blood 查询加工单元对应的入口出口物料流转情况，需要查询出包含完整分卷/并卷物料流转情况的记录
4. 校验请求必填字段、机组配置、切片长度和完整物料关系：切片长度及成品长度必须为正；目标出口物料必须属于请求的机组和加工单元；同次物料关系的 mat_type 必须一致且为 0、1、2，其他类型明确报错。分卷/并卷顺序号按数值排序，检查缺失或重复的顺序号，不依赖查询返回顺序。基础数据不满足要求时，在计算和写入前返回失败。

### 数字钢卷切片长度生成

在加工单元对应的入口出口物料流转情况中，取对应出口物料的长度，根据 qm_biz_digital_factory 配置的精度，对出口物料长度进行切片划分，每个切片有其 piece_no，对应着出口物料的一段长度

### 剪切数据准备

本节按入口物料准备在线卷在卷取机上的剪切数据 `trHead`、`trTail`、`trSlice`，均保留在线运行方向和原始记录的长度口径。此阶段不转换成品方向、不分配到各出口卷，也不进行长度缩放；后续长度换算使用这些数据和完整的分卷/并卷关系。

表数据使用说明：

1. qm_mat_cells_blood 查询结果的各行 mat_type 值都一样，取第一条的 mat_type 值即可。
2. qm_dc_shear_log 查询结果的剪切实绩中，shear_type 的第三位（shear_type[2]）代表剪切类型，1 代表切头，5 代表分切，9 代表切尾；shear_device_code 以 tr 开头表示卷取机，以 por 开头表示开卷机。
3. 按 `in_mat_no + in_mat_repeat_prod_no + cell_code` 查询剪切实绩，仅汇总卷取机（`shear_device_code` 以 tr 开头）的记录。切头或切尾无记录时，对应总量为 0；分切无记录时，`trSlice` 为空数组。剪切长度统一换算为米。

#### 正常卷产出

1. mat_type = 0 时，qm_mat_cells_blood 查询结果只有一条数据。
2. qm_dc_shear_log 表查询该入口物料的剪切实绩
3. 计算该入口物料在卷取机上的切头量 `trHead`、切尾量 `trTail`：所有卷取机上切头的 shear_length 之和为 `trHead`，所有卷取机上切尾的 shear_length 之和为 `trTail`。

#### 并卷产出

1. mat_type = 1 时，qm_mat_cells_blood 查询结果有多条入口物料不一样，出口物料一样的数据，out_mat_sequence_no 标明了多个入口物料的焊接顺序，序号从 1 开始。
2. qm_dc_shear_log 表查询多条入口物料的剪切实绩
3. 计算每条入口物料在卷取机上的切头量 `trHead[i]`、切尾量 `trTail[i]`，其中 i 为按焊接顺序排列后的入口物料数组下标，从 0 开始：该入口物料所有卷取机上切头的 shear_length 之和为 `trHead[i]`，所有卷取机上切尾的 shear_length 之和为 `trTail[i]`。各入口的剪切量独立保存。

#### 分卷产出

1. mat_type = 2 时，qm_mat_cells_blood 查询结果有多条入口物料一样，出口物料不一样的数据，out_mat_sequence_no 标明了多个出口卷物料的切分顺序，序号从 1 开始。
2. qm_dc_shear_log 表查询入口物料的剪切实绩
3. 计算入口物料在卷取机上的切头量 `trHead`、切尾量 `trTail`、分切量 `trSlice[i]`：所有卷取机上切头的 shear_length 之和为 `trHead`，所有卷取机上切尾的 shear_length 之和为 `trTail`；对于分切，用 shear_no 区分每一次分切，卷取机上同一次 shear_no 内的所有 shear_length 之和为一次分切量。将各次分切按在线运行顺序排列，保存为 `trSlice[i]`，下标 i 从 0 开始。
4. 准备结果保留该入口的 `trHead`、`trTail` 和完整的 `trSlice` 数组，不在此处分配到出口卷。n 个出口卷对应着 n -1 个分切量。剪切记录的分切次数与实际分切次数不一致时，后续换算按完整出口卷关系处理：多出的分切记录忽略，缺少的分切量按 0 处理。

### 在线卷长度数据准备

在线卷长度按工艺段分别准备，取该段工艺参数表中当前入口物料的最大 `head_length` 作为 `coilLength`。各段使用各自的长度坐标和缩放系数，不能用某一段的最大长度代替其他段的在线卷长度。

1. 根据基础数据初始化取得的 `qm_biz_parameter` 配置，按 `ts_database + ts_table` 分组，确定各工艺段需要查询的时序库和表。同一段的多个参数共用一张表时，只查询一次在线卷长度。常规表名为 `<unit_code_lowercase>_process_<segement_code>`；FCL1 的 iron_loss 段使用 `fcl1_ironloss_iron_loss`，以配置的实际库表为准。工艺参数表中的机组代码使用小写。
2. 按 `in_mat_no + in_mat_repeat_prod_no + cell_code` 确定当前加工单元的入口物料，取得该入口物料的生产开始时间 `start_prod_time` 和生产结束时间 `end_prod_time`。分卷时必须覆盖同一入口对应的全部出口卷生产过程，不能只取目标出口卷的时间；若完整物料关系中同一入口有多条时间记录，取最早开始时间和最晚结束时间。并卷时分别确定每条入口物料的时间范围。
3. 将入口物料生产时间范围向前、向后各扩展 1 小时，得到查询范围 `[start_prod_time - 1h, end_prod_time + 1h]`，保证覆盖整个钢卷在各段的跟踪数据。时间按生产记录和 TDengine 查询使用的一致时区传递，保留时间精度。
4. 对每个工艺段、每条入口物料查询 `MAX(head_length)`。查询必须同时限定扩展后的 `ts` 范围、`coil_no = in_mat_no`、`repeat_prod_no = in_mat_repeat_prod_no` 和当前 `cell_code`，避免扩展时间范围后混入其他物料或加工单元的数据。`head_length` 的单位统一为米。

```sql
SELECT MAX(head_length) AS coil_length
FROM <ts_database>.<ts_table>
WHERE ts >= :queryStartTime
  AND ts <= :queryEndTime
  AND coil_no = :inMatNo
  AND repeat_prod_no = :inMatRepeatProdNo
  AND cell_code = :cellCode;
```

其中库表取自 `qm_biz_parameter` 配置，查询参数 `queryStartTime = start_prod_time - 1h`、`queryEndTime = end_prod_time + 1h`；其余参数分别为当前入口物料号、入口物料重复生产次数号和加工单元代码。

5. 查询结果按工艺段和入口物料标识保存：正常卷、分卷在每段保存同一入口的 `coilLength`，分卷的全部出口卷共用该入口在该段的完整长度；并卷在每段按入口焊接顺序保存 `coilLength[i]`，与 `trHead[i]`、`trTail[i]` 的入口顺序保持一致。后续换算时传入当前段的长度集合。
6. 入口物料生产时间缺失、开始时间晚于结束时间、该段无匹配工艺参数记录，或最大 `head_length` 为空、非正数时，报错并注明工艺段和入口物料标识，不使用其他工艺段长度或成品长度替代。

### 成品卷长度转在线卷长度

根据当前工艺段的在线卷长度，将成品卷上的位置或切片区间换算为入口在线卷上的位置或区间。正常卷、并卷、分卷分别计算；所有剪切数据统一使用前文准备的 `trHead`、`trTail`、`trSlice`，始终表示在线运行方向的卷取机剪切量，不另设成品方向的剪切变量。

卷取后头尾反转：在线切尾一侧对应成品带头，在线切头一侧对应成品带尾。成品长度与剪切记录合成的完整长度可能与当前段的在线长度存在差异，因此先计算 `lengthScale`，成品长度、剪切量和累计偏移统一参与缩放。每个工艺段单独计算，不能跨段复用缩放系数。

换算使用完整物料关系、各成品卷长度、原始剪切数据，以及当前段按入口物料号和重复生产次数号对应的在线卷长度。`outMatPos`、`outMatStart`、`outMatEnd` 均相对于当前目标成品卷带头；`coilPos`、`coilStart`、`coilEnd` 均相对于对应入口在线卷带头。所有长度单位为米，数组下标统一使用从 0 开始的 `i`。

#### 正常卷

一个入口在线卷对应一个成品卷。沿在线运行方向，完整长度依次由 `trHead`、成品保留段、`trTail` 组成；卷取反转后，从成品带头向前补齐的是 `trTail`。

```text
lengthScale = coilLength / (outMatLength + trHead + trTail)

coilPos = coilLength - (outMatPos + trTail) * lengthScale
```

两端对应关系：

```text
outMatPos = 0
    -> coilPos = coilLength - trTail * lengthScale

outMatPos = outMatLength
    -> coilPos = trHead * lengthScale
```

切片 `[outMatStart, outMatEnd]` 反转后，按在线坐标从小到大返回区间边界：

```text
coilStart = coilLength - (outMatEnd + trTail) * lengthScale
coilEnd = coilLength - (outMatStart + trTail) * lengthScale
```

例如 `outMatLength = 100`、`trHead = 5`、`trTail = 3`、`coilLength = 110`，则 `lengthScale = 110 / 108`。成品切片 `[0, 10]` 对应在线区间约 `[96.759259, 106.944444]`；整个成品对应约 `[5.092593, 106.944444]`。两侧剪切量均乘相同的缩放系数。

#### 并卷

多个入口在线卷焊接后产出一个成品卷。入口按 `out_mat_sequence_no` 数值升序排列，业务序号从 1 开始，数组下标 i 从 0 开始。`coilLength[i]`、`trHead[i]`、`trTail[i]` 始终对应同一入口。换算分为“按完整切片确定所属入口及段内坐标”和“按正常卷公式换算”两步。

第一步：按各入口去掉头尾后的长度比例，反向划分成品坐标，并将划分边界对齐到已有切片边界。

先计算理论贡献长度：

```text
coilRetainedLength[i] = coilLength[i] - trHead[i] - trTail[i]
outMatPartRatioLength[i] = outMatLength * coilRetainedLength[i] / sum(coilRetainedLength)
```

- `coilRetainedLength[i]`：当前段入口 i 扣除卷取机切头、切尾后的长度，单位米；用于确定划分成品坐标的比例，必须为正。
- `outMatPartRatioLength[i]`：按上述比例得到的理论成品贡献长度，单位米；所有理论贡献长度之和等于 `outMatLength`，仅用于确定理论划分边界。

卷取后头尾反转，成品贡献段的排列与入口焊接顺序相反。入口 1、2、3 的保留长度比为 1:2:3 时，成品从带头到带尾按 3:2:1 反向划分，分别归属入口 3、入口 2、入口 1。数组仍按入口焊接顺序保存。

划分必须以“数字钢卷切片长度生成”阶段产生的完整切片为单位。理论边界已经在切片边界上时保持不变；落在切片内部时，向成品坐标增大的方向移到该切片终点，使整片归属成品从带头到带尾排列时的前一个部分。这里的“前一个部分”指成品坐标较小的一侧，例如入口 3 与入口 2 的理论边界落入某切片时，该片全部归入口 3。

定义 `alignPieceEnd(position)`：若 position 为 0 或已是切片边界，原样返回；否则返回包含该位置的已有切片的终点。使用实际切片边界，包括末片的成品终点，不重新生成切片。所有理论边界都从原始比例累计计算，再分别对齐，不将前一次对齐产生的偏移累加到后续理论边界。

```text
outMatPartStart[i] = alignPieceEnd(
    outMatLength - sum(outMatPartRatioLength[0:i + 1]))
outMatPartEnd[i] = alignPieceEnd(
    outMatLength - sum(outMatPartRatioLength[0:i]))
outMatPartLength[i] = outMatPartEnd[i] - outMatPartStart[i]
```

`outMatPartStart[i]`、`outMatPartEnd[i]` 为对齐后的实际成品贡献边界，单位米；`outMatPartLength[i]` 为实际分配到入口 i 的完整切片总长。相邻部分共用同一个对齐边界，因此无重叠、无空隙，总长仍为 `outMatLength`。若多个理论边界落在同一个切片内，对齐后可重合，中间部分的贡献长度为 0，不分配切片，也不计算该入口的缩放系数。

按调整后的贡献区间确定切片所属入口 i，整个切片只属于一个入口。将成品位置减去该贡献段起点，得到相对于该部分带头的坐标：

```text
outMatPartPos = outMatPos - outMatPartStart[i]
```

例如成品位置属于入口 2 的贡献段时，减去排在它前面的入口 3 实际分配到的成品贡献长度。

第二步：将对齐后的所属贡献段视为一个成品卷，按正常卷公式转换到对应入口在线卷。

```text
lengthScale[i] = coilLength[i]
    / (outMatPartLength[i] + trHead[i] + trTail[i])

coilPos = coilLength[i] - (outMatPartPos + trTail[i]) * lengthScale[i]
```

各入口使用边界对齐后的实际贡献长度重新计算 `lengthScale[i]`，不使用理论贡献长度。切片整体归入一个入口后，直接将其两个端点转换为该贡献段内的坐标，再换算为该入口在线区间：

```text
outMatPartStartPos = outMatStart - outMatPartStart[i]
outMatPartEndPos = outMatEnd - outMatPartStart[i]

coilStart = coilLength[i]
    - (outMatPartEndPos + trTail[i]) * lengthScale[i]
coilEnd = coilLength[i]
    - (outMatPartStartPos + trTail[i]) * lengthScale[i]
```

每个切片返回一个带所属入口物料标识的在线区间。各入口在线坐标独立从 0 开始。

例如入口按焊接顺序的 `coilLength = [103, 205, 307]`、`trHead = [2, 3, 4]`、`trTail = [1, 2, 3]`，扣除头尾后的长度为 `[100, 200, 300]`，比例为 1:2:3。成品总长 540、切片长度 20 时，理论成品贡献长度为 `[90, 180, 270]`，从成品带头起算的两个内部理论边界为 270、450。

270 位于切片 `[260, 280)` 内，边界移到 280，整片归入口 3；450 位于切片 `[440, 460)` 内，边界移到 460，整片归入口 2。实际贡献区间按入口数组顺序为 `[460, 540]`、`[280, 460]`、`[0, 280]`，实际贡献长度为 `[80, 180, 280]`。

因此切片 `[260, 280)` 全部按入口 3 的 `lengthScale[2] = 307 / (280 + 4 + 3)` 换算；下一切片 `[280, 300)` 全部归入口 2，其段内坐标为 `[0, 20)`，按 `lengthScale[1] = 205 / (180 + 3 + 2)` 换算。成品位置 300 在入口 2 对应部分内的坐标为 `300 - 280 = 20`。

#### 分卷

一个入口在线卷切分成多个成品卷。出口按 `out_mat_sequence_no` 数值升序排列，即在线运行方向上的切分顺序，业务序号从 1 开始，数组下标 i 从 0 开始。`outMatLength[i]` 为各成品卷长度，所有出口共用当前段同一入口的 `coilLength`、`trHead`、`trTail` 和 `trSlice`。

以三个出口卷为例，沿在线运行方向，完整长度的组成如下：

```text
trHead → 卷1保留段 → trSlice[0] → 卷2保留段 → trSlice[1] → 卷3保留段 → trTail
```

分切量在归属上属于其后的出口卷：`trSlice[0]` 属于出口卷 2，`trSlice[1]` 属于出口卷 3。首个出口卷没有前置分切量；后续出口卷（`i >= 1`）对应的分切量为 `trSlice[i - 1]`。此归属用于确定累计范围，不将 `trHead`、`trTail` 改成出口卷数组。

每个成品卷在自己的保留段内头尾反转，成品位置从自己的带头重新计 0。将其中一个成品卷的坐标换算到整个入口卷时，需要补齐 `trTail`，以及比该成品业务序号更大的所有出口卷长度和它们各自对应的分切量，再从入口在线总长反向换算。

计算前，按出口卷数量确定实际所需的分切量个数，即出口卷数减 1。对准备阶段的分切数组建立换算用副本：按顺序保留所需记录，忽略多出的记录，末尾缺少的记录补 0。下文 `trSlice` 均指该副本，原始剪切记录保持不变；只有一个出口卷时，换算用分切数组为空。

全部出口成品长度补齐入口切头、切尾和实际所需的分切量后，与入口在线完整长度对齐：

```text
lengthScale = coilLength
    / (sum(outMatLength) + trHead + trTail + sum(trSlice))
```

计算从补齐后完整卷的在线尾端，到目标成品卷带头对应位置的未缩放累计距离：

```text
restoredOffset[i] = trTail
    + sum(outMatLength[i + 1:]) + sum(trSlice[i:])
```

`restoredOffset[i]` 为目标成品卷反向换算时需要补齐的长度，单位米。`outMatLength[i + 1:]` 表示当前卷之后、业务序号更大的全部出口卷长度；`trSlice[i:]` 表示这些后续卷各自对应的分切量，均从所示下标取到数组末尾，空数组求和为 0。当前卷自己的前置分切量不计入该偏移，每次分切量在累计路径中只计一次。

三个出口卷的补齐项分别为：

```text
restoredOffset[0] = trTail + outMatLength[1] + outMatLength[2]
    + trSlice[0] + trSlice[1]
restoredOffset[1] = trTail + outMatLength[2] + trSlice[1]
restoredOffset[2] = trTail
```

目标成品卷的位置、切片区间按与正常卷相同的反向关系换算，成品位置和全部补齐项一起缩放：

```text
coilPos = coilLength - (outMatPos + restoredOffset[i]) * lengthScale

coilStart = coilLength - (outMatEnd + restoredOffset[i]) * lengthScale
coilEnd = coilLength - (outMatStart + restoredOffset[i]) * lengthScale
```

当前成品卷带头对应其在线保留段尾端，成品带尾对应其在线保留段头端。末卷没有后续出口卷，只需补齐 `trTail`；首卷带尾对应在线位置 `trHead * lengthScale`。`trHead` 通过完整长度分母参与缩放。

例如 `outMatLength = [100, 200, 300]`、`trHead = 5`、`trTail = 3`、`trSlice = [2, 4]`、`coilLength = 675.4`，则 `lengthScale = 1.1`，`restoredOffset = [509, 307, 3]`。第一个出口卷需补 `3 + 200 + 300 + 2 + 4 = 509`；下标为 1 的第二个成品卷切片 `[0, 10]` 对应在线区间 `[326.7, 337.7]`。首卷带尾对应 `675.4 - (100 + 509) * 1.1 = 5.5`，末卷带头对应 `675.4 - 3 * 1.1 = 672.1`。

仅有一个出口卷时，后续卷长度和分切量均为空，`restoredOffset[0] = trTail`，公式直接退化为正常卷的 `coilPos = coilLength - (outMatPos + trTail) * lengthScale`。

#### 换算约束与区间查询

成品长度、当前段各入口在线长度和缩放分母必须为正，剪切量必须非负；并卷的每个 `coilRetainedLength[i]` 必须为正，实际贡献长度 `outMatPartLength[i]` 必须非负；长度为 0 的部分不分配切片并跳过换算。切片满足 `0 <= outMatStart < outMatEnd <= outMatLength`，分卷时使用目标卷的 `outMatLength[i]`。数据缺失、切片越界或长度不满足上述约束时报错，并注明当前工艺段及相关物料。

上述公式表示区间的几何边界，返回时统一满足 `coilStart < coilEnd`。正常卷、分卷的换算区间长度应等于 `(outMatEnd - outMatStart) * lengthScale`。并卷每个完整切片只映射到一个入口，其在线区间长度应等于 `(outMatEnd - outMatStart) * lengthScale[i]`，使用该切片所属入口在当前段的缩放系数。

成品切片按左闭右开查询，目标成品卷的最后一片包含成品终点；反向映射后相应为左开右闭。并卷贡献区间按对齐后的成品坐标左闭右开划分，仅包含最终成品终点的非空贡献段包含该终点；边界处的新切片属于从该边界开始的后一个部分。保留切片的端点开闭属性并随映射反转，避免切片重复归属。

### 工艺参数查询与切片取值

完成长度换算后，为每个成品切片查询各工艺段对应的参数值，并按同一个 `piece_no` 汇总。取值口径沿用《数字钢卷切片计算过程中的数据映射关系》：一个切片对应在线卷一段长度，数值工艺参数取这段长度内有效采样值的算术平均值。

1. 按 `qm_biz_parameter` 的 `ts_database + ts_table` 对参数分组，使用 `unique_key` 定位工艺参数字段，`name` 用于展示和错误定位，`value_type` 用于类型检查。动态库、表、列名只能来自已校验的配置，不能直接使用请求参数拼接。
2. 遍历每个工艺段，用该段的 `coilLength` 和前文规则换算各切片的在线区间。并卷时使用该段完成切片边界对齐后的入口归属和 `lengthScale[i]`，每片只查询所属入口；分卷时使用完整出口关系计算目标出口卷的偏移。
3. 使用入口生产时间前后各扩展 1 小时的范围，并同时限定 `coil_no`、`repeat_prod_no`、`cell_code` 和 `head_length` 区间。同一段的多个参数一起查询；批量查询后在内存按区间归片，或在数据库按切片区间聚合，均须保持同一取值和边界规则，避免每个参数单独查询。
4. 普通切片由成品左闭右开区间反转为在线左开右闭区间，查询使用 `head_length > coilStart AND head_length <= coilEnd`；目标成品最后一片包含成品终点，其在线下界也包含，使用 `head_length >= coilStart AND head_length <= coilEnd`。
5. 每个数值参数独立剔除 NULL、非数值及非有限值后计算平均值，分母为该参数的有效采样数。没有有效采样时写入 NULL，不以 0 代替，不借用相邻切片或其他物料数据。非数值参数不参与平均值计算，其取值规则须按后文待确认项确定。
6. 参数查询失败与查询成功但区间内没有采样必须区分：前者终止本次生成并返回失败；后者保留该切片，相关参数为 NULL。若整个工艺段没有记录导致在线卷长度无法取得，按前文约束报错。

普通切片的单个数值参数查询示意如下，最终包含成品终点的切片将下界比较改为 `>=`：

```sql
SELECT AVG(<unique_key>) AS parameter_value
FROM <ts_database>.<ts_table>
WHERE ts >= :queryStartTime
  AND ts <= :queryEndTime
  AND coil_no = :inMatNo
  AND repeat_prod_no = :inMatRepeatProdNo
  AND cell_code = :cellCode
  AND head_length > :coilStart
  AND head_length <= :coilEnd;
```

数据库聚合方案须确认字段类型和异常采样的处理与上述规则一致。区间计算保留精度，不先将在线区间取整；平均值的存储精度与舍入规则按参数定义及目标字段类型处理，尚未定义的规则见后文待确认项。

### 表面缺陷关联

根据《数字钢卷切片相关数据源介绍》，CP1、FCL1 需要关联 `qm_defect_surface_check` 中的表面缺陷。切片表存缺陷组标识，不复制缺陷明细。

1. 确定表检仪 `y_position` 所属的在线长度坐标及对应工艺段，使用该段在线长度和换算关系取得切片的在线区间。不能任意使用其他工艺段的区间，也不能直接使用成品坐标与 `y_position` 比较；表检坐标与工艺段的对应关系尚须确认。
2. 按 `unit_code + in_mat_no + ts 范围` 查询缺陷，时间范围沿用当前入口物料生产开始前 1 小时至结束后 1 小时，机组代码按数据源要求使用大写。该表已给出的查询键不包含重复生产次数号，因此必须保留入口生产时间限制，避免同号物料不同生产批次混入。
3. 按 `y_position` 判断缺陷是否落在切片的在线区间，使用与参数取值一致的端点开闭规则。并卷整片只关联其所属入口的缺陷；分卷只关联目标出口卷对应的在线保留区间，剪切去掉的区间不归入成品切片。
4. 将每条命中的缺陷组标识拼接为 `unit_code@@in_mat_no@@ts@@source_id`，其中 ts 保留数据源返回的原始时间戳精度，统一按约定格式序列化。同一切片内按完整标识去重，结果写入 `defect_groups`，类型为 JSON 字符串数组文本。
5. 查询成功但没有缺陷时写入 `[]`；不需要表检关联的机组同样写入 `[]`。需要关联的机组查询失败时返回失败，不将失败伪装成无缺陷。数组序列化后必须检查目标字段长度，超过 `VARCHAR(4096)` 容量时明确报错，不截断标识或 JSON。

当前数据源仅提供以 `y_position` 为位置的关联依据，先按缺陷点位置归片。若要按缺陷纵向覆盖范围关联多片，需要另行补充缺陷长度字段及覆盖规则。

### 切片存储表结构准备

表结构遵循《数字钢卷切片表存储细则》，使用 `quality-ts` 提供的接口建表、核对新增列和写入数据。本步骤在基础配置加载后、正式计算及写入前执行，同次调用固定使用同一份参数配置快照。

1. 从 `qm_biz_digital_factory` 取得目标 `piece_ts_database`、`piece_ts_table`，不要按机组名重新推测写入位置。
2. 核对固定字段 `ts`、`unit_code`、`out_mat_no`、`out_mat_repeat_prod_no`、`cell_code`、`piece_length`、`piece_no`、`defect_groups`。每个机组共用一张切片表。
3. 取得该机组最新 `qm_biz_parameter`，按 `unique_key` 准备动态参数列并核对 `value_type`。重复配置若指向不同来源或存在类型冲突，须报错，不能由遍历顺序决定最终取值；参数名不得与固定字段冲突。
4. 调用 `quality-ts` 的建表/核对能力，表不存在则创建，已有表只新增缺失列，不删除历史参数列。已有列类型冲突时中止并报告配置错误，不通过删除再重建列来变更类型。
5. 当前仓库 `quality-ts` 的 `POST /manage/table/create` 在列式模式下包含建表和列差异处理，但其类型变更分支会先删除再新增字段，与本方案“只新增列”约束冲突。接入前须增加类型冲突保护或提供只新增列的能力，不能直接将类型冲突配置传入现有流程。

### 切片记录组装与写入

将前述查询结果按目标出口卷的 `piece_no` 合并，每个切片一条记录。存储固定字段如下，动态参数列使用配置中的 `unique_key`：

| 字段 | 数据来源与约束 |
| --- | --- |
| `ts` | 本次生成记录时间，来源于创建时间；写入前按目标数据库精度分配，同一目标表内各记录时间必须可区分，具体分配及重试复用策略见待确认项 |
| `unit_code` | 请求机组代码，按物料侧约定使用大写 |
| `out_mat_no` | 本次请求的目标出口物料号 |
| `out_mat_repeat_prod_no` | 目标出口物料重复生产次数号，与物料号共同标识该次出口物料 |
| `cell_code` | 本次请求的加工单元代码 |
| `piece_no` | 从成品带头开始递增的切片业务序号，从 1 开始；数组下标仍从 0 开始 |
| `piece_length` | 当前切片实际长度，单位米；末片不足配置长度时写实际长度 |
| `defect_groups` | 去重后的缺陷组标识 JSON 数组文本，无缺陷时为 `[]` |
| 动态参数列 | 当前切片在对应工艺段换算区间内的参数聚合值；无有效采样为 NULL |

1. 写入前检查切片总数、序号连续性和实际长度之和，保证覆盖 `[0, outMatLength]` 且末片不越界。固定切片长度来自 `qm_biz_digital_factory.piece_length`，不得因为某个参数缺失而删除切片。
2. 将同一 `piece_no` 的各工艺段参数和缺陷结果合并后，再通过 `quality-ts` 按其请求结构批量写入，不能将不同工艺段写成多条成品切片记录。
3. 存储细则是一片一行、参数为动态列的结构，应对接列式写入能力。当前仓库对应路径为 `POST /data/db/{database}/table/{table}/_column`，具体请求结构和批量上限按服务契约适配。
4. 同一张时序表不能让所有切片共用同一个创建时间戳。仅按 `piece_no` 生成时间也不能区分不同出口卷；必须同时解决跨卷、并发和重试时的时间键冲突。时间分配方案未确定前不能认为持久化环节已完整。
5. 检查每批调用返回的业务状态，全部批次成功后才能认定本次生成成功。部分批次失败时保留失败状态与可重试上下文，不向调用方报告成功。

### 重复调用、失败处理与接口返回

本接口处理范围为请求指定的一个出口物料和加工单元，完整分卷/并卷关系仅用于换算，不应在本次调用中顺带生成或覆盖其他出口卷的数据。

1. 以 `unitCode + outMatNo + outMatRepeatProdNo + cellCode` 标识一次目标物料生成任务，重复或并发调用同一目标时需要串行执行或返回明确的处理中状态，不允许两份结果交叉写入。
2. 重算时必须处理该目标的全部旧切片，尤其是切片数量减少时的旧尾部记录。仅用新时间戳追加或仅覆盖相同 `piece_no` 均不足以保证幂等；最终采用稳定时间键重试、替换旧结果或版本切换的方案，须结合后文待确认项落实。
3. 先完成配置校验、表结构核对、各段长度校验和结果计算，再进入结果替换/写入阶段。不要在基础数据尚未校验通过前删除上一份可用结果。
4. `quality-ts` 写入、旧结果清理以及任务状态不属于同一个本地数据库事务，不能用单个 `@Transactional` 假定整体回滚。需要明确失败恢复、旧结果保留和重试策略，并确保消费者不会将部分写入误认为完整结果。
5. 接口沿用项目统一响应。当前 Controller 返回 `R<Void>`，可继续用成功/失败状态表达处理结果；成功必须表示全部结果已落库。若后续改为异步，则须另行定义任务标识和状态查询接口，不能让现有同步成功响应同时表达“仅已受理”。
6. 当前 `quality-mat` 的 Service 只转发 `quality-calc`，Feign 调用返回业务结果后未校验 `code`，Controller 随后直接返回成功。实现时须检查下游业务状态并向上抛出失败，不能只依赖 HTTP 是否成功；服务实现位置和调用链改造还需落实。
7. 日志记录目标物料标识、参数配置来源、工艺段、切片数量、耗时、缺采样数量和失败批次，保留定位所需上下文；不逐条打印完整采样或缺陷数据。
